# RAG 项目专业评审报告（2026-10-13）

**评审对象**：`RAG/`（医疗 RAG 系统，src 约 1.75 万行 / 21 业务模块；tests 12 文件 58 用例）
**评审方式**：只读四路并行深审（检索核心链路 / API 与安全层 / 数据摄取-解析-索引链路 / 工程化与测试 CI），全部结论附 文件:行号 证据；四条最承重结论已由主评审人二次亲证。
**对照基线**：2026-09-28、2026-10-12 两轮评审报告。

---

## 一、总体结论

**代码本体的工程素养处于同类项目的上游水平，但存在系统性风险：高质量的安全设计被三个"默认关闭/默认不安全"的接线缺口抵消，且近一半现行工作未纳入版本控制——项目正处于"强实现 + 弱交付"的失衡状态。**

| 维度 | 评级 | 一句话结论 |
|---|---|---|
| 检索核心（RRF/门禁/ACL） | 良好偏优 | RRF 数学正确、fail-closed 文化一以贯之；但门禁默认不启用 + 分数空间不校验 |
| API 与安全 | 中上 | 鉴权/租户隔离/上传校验四高危面扎实；3 个 fail-open 默认值 |
| 数据与索引链路 | 良好 | Outbox/幂等/租约设计优秀；公开知识 ingest 有一处致命一致性缺陷 |
| 工程化（git/CI/测试） | **弱，阻断级** | 121 项变更未提交、CI 引用已丢失的守卫测试、frontend/src 不存在 |

**问题总数**：致命 5 / 严重 10 / 警告 15+ / 建议若干（按四路合并去重后）。

## 二、致命问题（P0，必须修复）

### P0-1 公开知识 ingest 在 DB commit 前写外部索引——幽灵索引记录
- **位置**：`src/medical_rag/knowledge/ingest_service.py:300-308`（已亲证）
- **原文**：`self._index_batch(indexed_records)`（OpenSearch 外部副作用）→ … → `self.session.commit()`
- **影响**：commit 失败（连接抖动/约束冲突/崩溃）时索引侧已有记录而 DB 无对应行 → 可被检索、无法对账、reconciliation 修不了（hash 对不上）。与私文档链路（ParsingService 正确地 commit 后再跑 IndexWorker）形成同库内的双重标准。
- **修复**：`_index_batch` 移到 `commit()` 成功之后（at-least-once + 幂等 upsert），或走已有 Outbox/IndexJob 通道。

### P0-2 拒答门禁不校验 `vector_score_space`——新校准件与存储分数空间不相容
- **位置**：`src/medical_rag/retrieval/service.py:529`（已亲证）+ `opensearch_store.py:28` + `opensearch_writer.py:252` + `config/calibration/cosine-gate-2026-10-12.json`
- **证据**：`gated = [r for r in vector if r.vector_score >= threshold]` 无任何空间校验；存储硬编码 `VECTOR_SCORE_SPACE = "l2_inv"` 且 mapping 从未声明 `space_type`；而 2026-10-12 校准件写的是 `"score_space": "cosinesimil", "cosine_threshold": 0.78`。
- **影响**：按该件部署会把 l2_inv 分数与 cosinesimil 阈值比较 → 真相关文档被系统性误杀、大规模错误拒答。这正是 `contracts.py:241-245` 注释里自己警告过的"0.53↔0.5155 数值巧合"事故的配置版复发。
- **修复**：门禁执行前逐条校验 `record.vector_score_space == self.score_space`，不匹配/None → fail-closed（空结果 + `score_space_mismatch` 诊断）；写入器增加 `space_type` 参数并在 mapping 兼容检查中校验。

### P0-3 拒答门禁默认部署不生效——「无关查询不拒答」缺陷在线上默认仍未关闭
- **位置**：`core/config.py:102`（`calibration_artifact_path: str | None = None`）+ `docker-compose.yml`（无 CALIBRATION_ARTIFACT_PATH）+ `api/composition.py:151-166`
- **影响**：代码修复与 32 例回归网俱在，但默认配置落入 `GatePolicy.TOP_K`（无硬门禁）。曾量化的"拒答准确率 0.00、检索层唯一 P0"的关闭动作被留给一次容易遗漏的运维配置。
- **修复**：默认指向已验证的 `cosine-gate-2026-09-26.json`（l2_inv/0.50 与存储一致）；或非 dev 环境对 `TOP_K` 策略打 WARNING 并暴露启动自检指标；compose 显式接线。

### P0-4 近一半现行工作未提交——重演"丢失事故"的风险敞口
- **证据**：`git status` 121 项（79 modified + 38+ untracked，已亲证）；untracked 含 `src/medical_rag/provenance/` 整个模块、`tests/{contract,eval,unit}/` 9 个文件、`alembic/versions/0010_*`、`scripts/run_worker.py`、**`uv.lock` 本身**（280 包锁文件不入库 = 锁定形同虚设）。
- **背景**：项目刚经历 2026-10 git 对象库损坏、84 个测试文件全丢。当前状态等于把鸡蛋再次放在 git 索引之外。
- **修复**：立即分批 commit；优先 tests/、provenance/、0010 迁移、uv.lock。

### P0-5 frontend/ 是"只有构建产物的空壳"
- **证据**：`frontend/src` **不存在**（已亲证）；package.json 声明完整 Vue3+Pinia+vitest 技术栈；`docker-compose.yml` 的 frontend service 仍 `build: ./frontend` → compose 全栈起不来。
- **修复**：找回源码，或先从 compose 移除 frontend service 并在 README 声明现状。

## 四、警告级问题（P2，择要）

1. **限流仅登录端点且为进程内存实现**（`routes/auth.py:25`、`throttle.py`）：多副本失效；代理后所有用户共享 `ip:<proxy>` 键，5 次失败锁死全员 300s。→ Redis 化。
2. **JWT 无撤销（无 jti/黑名单）**，仅 60 分钟 TTL；补偿：同意校验实时生效（数据面），但审计面仍可持续。
3. **密码最小长度 = 1**（`routes/auth.py:36`）；phone 上限 200。
4. **上传/登录均无审计事件**：最敏感的 PHI 文档入库动作零审计痕迹（上轮 P0-5 至今未动，`AuditAction` 枚举无 upload）。
5. **药物词表裸子串误拦知识问询**（`safety/rules.py:23-35`）："停药后需要注意什么" 被 SAFE_TEMPLATE 挡在检索外——与 P1-3 相反方向的可用性损耗。
6. **rerank 后 `diagnostics["ranks"]` 过期**、`vector_score_space` 诊断类型不稳定（str|list|str）。
7. **legacy `EXPLICIT_THRESHOLD` 门禁在单次调用路径静默失效**（`service.py:264-279` 只对 COSINE_ABSOLUTE fail-closed）。
8. **`delete_by_query` 后无 refresh** → 删除与检索 ~1s 竞态窗口。
9. **上传超限返回 500 而非 413**（`file_policy.py:73` 的 ValueError 不在 handler 体系内）。
10. **api 端口仍绑全接口**（compose `"8000:8000"`，其余服务全部回环）——上轮 P2-2 未修。
11. **删除服务 failure_details 只存异常类名**，排障信息丢失。
12. **EmbeddedAdapter 固定 0.05s 线性重试、无退避无抖动**，4xx 也重试。
13. **.gitignore 缺口**：`tmp/`、`eval_out/`、`.i18n_work/`、`agent_lab*/` 未忽略，`git add -A` 会全部入库。
14. **根目录卫生**：`.env`（含网关 key）、`medical_rag.db(+.bak)`、乱码空文件仍在目录内（该目录本身即微信传输产物，随目录外发即泄漏）。
15. **本地 ONNX 推理并发安全依赖外部库隐式保证**（`local_embedding.py:170-218` 锁只保护加载不保护 embed）。

## 五、测试与 CI 现状

**测试是"高质量的纵深回归网而非广度覆盖"**：58 例中 32 例围死拒答门禁（含变异对照、部署件解析守卫、三档启动拦截）——这是把唯一量化 P0 修死的正确策略。但：

**CI 缺口**：无覆盖率门禁（pytest-cov 已在 dev 依赖却未用）、无 pip-audit/gitleaks、uv.lock 未被 CI 消费（`pip install -e` 而非 `uv sync --locked`）、无前端 job。

## 七、正向评价（有据可查的资产）

1. **「检索不可用」与「证据不足」语义分离**贯穿顶层设计（5 个 reason 常量），患者得到两种完全不同的答复——医疗场景的正确产品决策。
2. **score 空间意识**：把"kNN `_score` 是 1/(1+L2²) 而非余弦"写进类型契约并贯穿 diagnostics——绝大多数 RAG 项目不知道自己分数是什么语义。
3. **三层 fail-closed ACL**（查询体 term + 记录层复核 + legacy 无标记默认不可检索）+ 公开写入器从源头拒 PHI 字段。
4. **JWT 教科书级**：算法白名单、强制 iss/aud、dev 用随机临时密钥、密钥 ≥32 字节启动校验；历史上"DSN 复用为签名密钥"已修复留痕。
5. **Outbox payload 强制剥离 PHI**——合规内建到数据结构层而非依赖自觉。
6. **登录防御成熟**：哑 bcrypt 抹平时序、统一错误消息防枚举、限流先于数据库。
7. **test_rejection_gate.py 是回归测试范本**（变异对照证明测试非空转）。
8. **CI 的"事故驱动防御"注释文化**：每条 job 注明防的历史事故，可审计。
9. **工程事故的诚实记录**（tests/README.md 交代 84 文件丢失与重建优先级）。
10. **CachedEmbeddingModel 教科书级有界缓存**；SemanticChunker 的 overlap 计入预算、边界完备、provenance 贯穿无断点。
