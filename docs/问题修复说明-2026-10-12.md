## P1-1 聊天幂等去重 TOCTOU 竞态

**修复内容**（三层）：
1. `domain/models.py` — `ix_chat_messages_client_request_id` 升级为 `unique=True`（数据库层最终防线；NULL 不参与唯一性，普通消息不受影响）。
2. 新增迁移 `alembic/versions/0009_chat_idempotency_unique_index.py` — 幂等地删除旧非唯一索引、创建 `ux_chat_messages_session_client_request_id`（沿用 0008 的 inspector + 方言目录双查策略），含 downgrade。
3. `chat/orchestrator.py` `_persist_answer` — `commit()` 包 `try/except IntegrityError`：并发败者回滚后回读既有记录、按重复请求处理（不再 500）；与幂等键无关的完整性冲突向上抛出，走"持久化失败不阻断投递"路径。

**部署注意**：需执行 `alembic upgrade head`；若存量数据已有重复 `(session_id, client_request_id)`，建唯一索引会失败，需先清重。

## P1-5 vector_score 语义消歧

1. `retrieval/opensearch_store.py` — 新增常量 `VECTOR_SCORE_SPACE = "l2_inv"`（OpenSearch kNN 默认 L2 → `_score = 1/(1+L2²)`，非余弦；含"将来改 cosinesimil 须同步改常量并重建索引"的注释）。
2. `retrieval/contracts.py` — `SearchRecord` 新增 `vector_score_space: str | None` 字段（默认 None = 语义未知，禁止用于阈值比较）。
3. `_record_from_hit` — 重写分数读取逻辑：**只在各自检索模式下读分**。旧实现 `source.get("bm25_score", ...)` 在文档残留同名字段时会把词法分漏进 vector 记录（反之亦然）污染诊断；现按 `score_mode` 显式分流。vector 记录携带 `vector_score_space="l2_inv"`。
4. `retrieval/service.py` — diagnostics 透出 `vector_score_space`（多值列清单或 `unknown`）；`chat/orchestrator.py` 白名单放行该键。

## P1-6 rerank 与门禁/评分脱节

`retrieval/service.py` `_retrieve_hybrid`：
- **rerank 移到门禁之前**：融合候选 → rerank（`rerank_limit` 头部重排）→ 阈值/rank 门禁 → top_k。被门禁误杀的候选现在可以先被 rerank 复活。rerank 失败仍静默保留融合序，不放大故障。
- 诊断新增 `rerank_before_gate: True`、`score_semantics: "rrf_fused_raw"`（Evidence.score 是原始 RRF 融合分，禁止当阈值/置信度用，orchestrator 白名单已放行）。
- 最终截断依据从旧的 `rerank_candidates`（门禁前切片）修正为门禁后的 `fused`。

## P1-7 引用正则假阳性拒绝面

`chat/citations.py`：
- `citation_pattern` 从「任意 `[字母数字]`」收紧到**证据 ID 形态**：UUID，或"同时含字母与数字"的短 token（e1、e1c1、pub-12）。纯数字 `[1]`/`[2023]`、含 CJK `[注1]`、纯字母 `[note]` 一律视为正文。提取/段落覆盖/句末锚定/strip 四处共享同一模式。
- `_ends_with_citation` 从「以 `]` 结尾」收紧为「以证据 ID 引用结尾」（`match.end() == len(core)`），消除 `[1]` 假通过。
- 实测：`[1]/[2023]/[注1]/[click](url)` 全部排除；`[e1c1]`、大小写 UUID 正常提取。

**残余风险**：若未来证据 ID 形态变化（如新增纯字母 ID），需同步调整该模式——模式处已加注释说明。

### T3 标定分派恢复（按 visibility 分派）

- `retrieval/service.py`：一致性检查由**单一 `index_version` 全局比对**改为**按可见性分派**
  （新增静态方法 `_record_breaks_calibration`）：
  - `embedding_model` → **全局**校验（向量空间身份不因索引而异，保持既有行为）；
  - `index_version` → **按可见性分派**（`public` → `public_index_version`，
    `private` → `private_index_version`）；期望版本无法解析（未知可见性）→ 视为破坏，fail-closed。
  - 不符记录按 `id` **去重**（同一条被词法/向量两路命中只计一次），避免 `mismatch_count` 虚高、
    避免同一条占满只保留 5 条的 `mismatch_records`。
  - 新增诊断键 `calibration_mismatch_count`（不符记录数）与 `calibration_mismatch_records`
    （最多 5 条，仅 `id`/`visibility`/`index_version`/`embedding_model`，**不含正文** — 防 PHI 出诊断面，I8）。
- `chat/orchestrator.py` 诊断白名单补上述 2 个新键。
- **修复目标（09-28 spec 的 P0-1）**：此前只要配了 artifact，**双索引混合作用域**
  （`LAB_INDICATOR`/`ORDINARY`，"我的血红蛋白是多少"这类核心场景）的每个查询都返回 0 条 +
  `calibration_artifact_mismatch` —— 引入门禁反而让系统不可用。修复后混合作用域恢复正常。

### T4 组装与启动自检

- `api/app.py`：新增模块级 `_assert_configured_gate_is_active(app, settings)`，
  在 lifespan 的 **`try/except` 之外、`yield` 之前**调用。
  - 条件用「**路径非空**」而非「artifact 非 None」：`artifact` 只在 `RetrievalService`
    构造成功后才存在；若以 artifact 为条件，则"配了路径 + 装配失败 + 非生产环境（异常被吞）"
    这一组合会**跳过自检**——恰好漏掉最该拦的情形。
  - 三档拦截：编排器未装配 / 检索服务未持 artifact / `gate_policy` 非 `COSINE_ABSOLUTE`
    → 均抛 `RuntimeError`，**杜绝"配了 artifact 却静默退回 TOP_K（永不拒答）"的实例上线**。
  - 成功时记 `cosine gate enabled: threshold/score_space/public/private` 日志。
  - 未配置路径 → 直接返回（`TOP_K` 是预期状态，对"从未启用"的部署行为逐字节不变）。
