# 现有真实链路日志基线

这份报告只使用工作区中已经存在的本地真实链路输出，不把它们称为生产业务数据，也没有补造问题或回答。

当前工作区没有可验证的生产业务日志导出，因此本报告不计算线上命中率、线上拒答率或线上 faithfulness。

本地数据库的 27 条记录已脱敏导出：11 个不同问题，覆盖 `health_education` 16 条、`lab_indicator` 6 条、`report_explanation` 5 条；27 条均有引用证据 ID。原始会话、租户、患者 ID 和回答正文没有写入导出文件，人工标签仍待补齐。

这些记录共包含 103 次引用、14 个不同证据 ID；其中 11 个来自 `knowledge_chunks`，另外 3 个来自私有 `evidence_units`。14 个 ID 都能在本地数据库解析；复核后确认其中 1 个的父文档和版本已被删除，因此它是历史引用，不是当前可检索证据。OpenSearch 对账与生命周期复核均未发现当前活跃索引漂移，也没有未解析 ID。

## 已观测结果

- 端到端医学回答验收：10/10 通过引用校验；中位延迟 58.5 秒，P95 83.6 秒。
- 重复回答探针：同一问题请求 8 次，5 次 `answered`、3 次 `degraded`，引用抖动率 37.5%，中位延迟 49.5 秒。
- 分流验收：闲聊开关开启时 3 条闲聊均走 casual；医学探针没有被误判为 casual；安全问题走安全模板；关闭闲聊后 3 条闲聊均回到医学证据不足路径。
- Faithfulness：20 个答案中只有 8 个进入评分，66 个声明中 62 个弃权，弃权率 93.9%，当前结论为 `undecidable`。
- CoverageRouter：现有 19 条样本全部通过，但其中只有 9 条标记为 `observed_local_chat`，另外 10 条是 `synthetic_boundary`。

## 真实问题清单

目前最明确的两个问题是：

1. 同一问题的回答和引用不稳定，重复探针的 degraded 比例为 3/8；
2. faithfulness 评测的有效答案和可判定声明太少，不能得出质量结论。

本地数据库样本还显示问题重复度较高：27 条记录只有 11 个不同问题，不能直接当作 27 个独立业务样本。后续统计必须按问题、会话和意图分层，避免重复探针放大结果。

我已基于实际记录中的 `intent`、问题措辞和可解析证据生成一版**初步标签**：24 条建议走 RAG，2 条建议先澄清，1 条建议走带明确边界的 RAG；24 条暂判为可回答，3 条暂判为部分可回答，其中 8 条需要医学复核。这些标签保存在 [observed_local_db_cases.provisional_review.jsonl](../eval/observed_local_db_cases.provisional_review.jsonl)，状态明确为 `assistant_provisional`，不能当作最终医学金标准。

引用结构检查显示：27/27 条回答正文都包含其 metadata 中登记的引用 ID；但相同问题的引用集合仍会变化，重复的生活方式问题 11 次出现了 8 组不同引用集合，说明排序和回答稳定性仍需单独评估。回答正文没有写入脱敏导出，因此声明级 faithfulness 仍不能仅靠该导出文件判定。生命周期复核后的结构重评见 [observed_local_db_post_reconciliation_structural_eval.json](../eval_out/observed_local_db_post_reconciliation_structural_eval.json)。

只读 OpenSearch 对账最初发现：14 个唯一引用 ID 中有 13 个存在于公共/私有别名，1 个（`6e8a499b-f28c-471b-97aa-e80cd4285157`）不在两个 OpenSearch 别名中。随后对该 ID 做了数据库生命周期复核：它的 `IndexJob` 在回答生成前已成功（`2026-10-08 05:47:25`），但父文档和版本在 `2026-10-08 05:53:11` 被本地验收清理流程删除，OpenSearch 当前也没有该 ID 或同 `evidence_unit_id` 的残留。因此不能重新索引；重新索引会复活已删除的患者数据。原始扫描保留在 [observed_local_db_index_audit.json](../eval_out/observed_local_db_index_audit.json)，处置结论见 [observed_local_db_index_resolution.json](../eval_out/observed_local_db_index_resolution.json)。

这两个问题都不能通过冻结 Test v2.1 反向调参解决。前者需要保留真实请求的完整 trace，后者需要保存足够的回答、证据和声明拆分结果。

## 下一步输入

需要从实际业务系统导出一批脱敏日志，转换成 [real_traffic_cases.template.jsonl](../eval/real_traffic_cases.template.jsonl) 格式。第一批建议 50～100 条，并保留原始路由、检索证据、回答和引用信息。导入后再分别计算：

- 路由误拒、拒答漏放和高风险漏转；
- Recall@3、MRR、nDCG 和错误范围命中；
- 声明级 `entailed`、`unsupported`、`contradicted` 和弃权率；
- 隐私泄漏、危险建议和引用稳定性。

## 临时规则-only faithfulness 重放

The original SQLite answer bodies were materialized only in a temporary directory and deleted after evaluation. The deterministic replay covered 27 answers and 371 claims: 30 rule-supported, 331 abstained, and 4 rule flags; abstention was 89.2%, so the verdict is not suitable as a production gate. Manual evidence review of the three hemoglobin answers found that all four flags were false positives: the answers reported 105 g/L below the cited 130–175 g/L interval, which agrees with the evidence and the wording “偏低”. No evidence contradiction was found in those four flags. The full run remains `undecidable`; details are in `eval_out/observed_local_db_faithfulness_manual_review.json`.
