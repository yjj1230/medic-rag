## 2. Docker Desktop 引擎反复自灭 —— 根因与修复

### 症状
`docker desktop start` 成功 → 引擎 UP 29.6.2 → 三容器 UP、端口全开 → **约 1–3 分钟后引擎再次消失**
（`npipe:////./pipe/dockerDesktopLinuxEngine` 不存在）→ 检索层 `lexical_error/vector_error` → chat 降级。

### 根因
`%LOCALAPPDATA%\Docker\log\host\Docker Desktop.exe.log` 记录：

```
backend process exited: exit status 0x40010004
```

`0x40010004` = **`DBG_TERMINATE_PROCESS`**。该进程**被 Job Object 连带终止**：
从后台 shell / 子进程启动 Docker Desktop 时，子进程被纳入调用方的 Job Object；
调用方进程一退出，OS 便杀掉整棵作业树。**事件日志无 AppCrash** —— 不是崩溃，是外部终止。

### 修复（已验证）
用 **WMI 脱离 Job Object** 启动，使 Docker Desktop 不在调用方作业树内：

```powershell
([wmiclass]'\\.\root\cimv2:Win32_Process').Create('"C:\Program Files\Docker\Docker\Docker Desktop.exe"')
# 返回 ReturnValue=0 ProcessId=xxxx
```

修复后**稳定运行 10 分钟以上**（此前 1–3 分钟必崩）。
恢复序列：等引擎 `docker info` 成功 → `docker start medical_rag_{opensearch,redis,minio}` → 轮询 9200/9000/6380。

## 3. chat 必然降级 —— 三个独立根因

> 对照实验证明：**检索与模型链路本身可用**。在放宽超时后，`glm-5.3-flash` 能产出
> 6 段、带完整引用的中文医学答案（1051 字符）。卡点全在下列三处。

### 根因 ①（最高频）超时死配置 —— 120s 从未生效

| 位置 | 现状 |
|---|---|
| `.env` `MODEL_REQUEST_TIMEOUT_SECONDS` | `120`（**未被使用**） |
| `core/config.py:54` `model_request_timeout_seconds` | 字段存在，默认 30.0 |
| `chat/prompts.py:31` `build_chat_request()` | **不传** `timeout_seconds` |
| `models/contracts.py:30` `ChatRequest.timeout_seconds` | 取默认 **30.0s** |
| `chat/orchestrator.py:475` | `timeout_seconds=min(request.timeout_seconds, remaining)` |
| `chat/orchestrator.py:103` `total_timeout_seconds` | 默认 **60.0**，亦非来自配置 |

真实 `glm-5.3-flash` 延迟实测 **24s / 30s / 35.7s / 121.7s**（波动极大）→ 稳定触发 `ModelTimeout`
→ 返回"模型服务暂时不可用"。**120s 是完全的死配置。**

### 根因 ② 引用校验器与真实模型输出不兼容

`chat/citations.py:_check_sentence_citations` 按 `。！？；` 切句，并**要求每一句末尾**都带 `[evidence-id]`。
真实模型按**段落级**标注引用（每段末尾一个 ID），实测 **26 句 / 15 句缺句末引用**
→ `UnsupportedClaim("回答中存在未在句末标注证据引用的医学结论句")` → 降级。

示例（模型真实输出片段）：

```
**一、饮食方面**
减少钠盐摄入是控制血压的基础措施之一。资料建议每日食盐摄入量不超过 5 克…（多句无标记）
…有助于血压管理 [39f7ae94-...]。   ← 仅段落末尾有标记
```

### 根因 ③ `max_output_tokens=1200` 可能截断长回答

同题多次实测返回字符数 1051 → 379 →（波动）；被截断时可能出现「引用了不在本次候选集内的 ID」
→ `UnsupportedClaim("回答引用了不存在的证据")`（**间歇性**出现，取决于截断位置）。

### 关联观察
模型延迟极不稳定（24–122s）意味着即使把 120s 接通，121s 那次仍会超；需一并核对
`total_timeout_seconds` 与网关侧限制。

## 4. 建议修复（待批准）

| 优先 | 改动 | 文件 | 性质 |
|---|---|---|---|
| P0 | 把 `settings.model_request_timeout_seconds` 接入 `build_chat_request`（或组合根注入 `ChatOrchestrator`） | `chat/prompts.py` / `api/composition.py` | 接线，行为可测 |
| P0 | 让 `total_timeout_seconds` 来自配置，且 ≥ 模型单次预算 | `api/composition.py:193` / `chat/orchestrator.py:103` | 接线 |
| P1 | 引用校验放宽为**段落级锚定**或**句末可继承**（需 spec 明确医学安全边界，不得放松到失去句级约束） | `chat/citations.py:136-152` | 规则变更，须 spec |
| P2 | 复核 `max_output_tokens`（1200 → 视回答长度上调） | `models/contracts.py:31` | 参数 |

> ⚠️ 根因 ② 涉及**医学安全校验规则**，改动必须走 spec + 测试（含负样本），
> 不得仅为"让模型通过"而放松校验；正确方向是**对齐提示词与校验器的引用粒度约定**。
