# P0-P1 问题修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with verification checkpoints.

**Goal:** 按 P0 到 P1 的优先级修复医疗 RAG 的安全、数据一致性、OCR、部署和可观测性问题，保持边界清晰并避免跨模块补丁堆叠。

**Architecture:** 先在现有服务边界内补齐行为契约和回归测试，再修改最小生产代码。安全分类、身份生命周期、质量门禁、索引发布和部署配置分别保持独立；跨层交互通过现有协议、outbox 和依赖注入完成。

**Tech Stack:** Python 3.12、FastAPI、SQLAlchemy、Celery、OpenSearch、Vue 3、Pinia、Vitest、pytest、ruff、Docker Compose。

**Spec:** `docs/问题修复说明-2026-10-06.md`

## Global Constraints

- P0 必须全部关闭后才能进入 P1。
- 每个行为修复必须先写一个能够复现原问题的失败测试。
- 不新增全局状态；优先复用现有 service、outbox、依赖注入和审计边界。
- 质量门禁保持 fail-closed：`NEEDS_REVIEW` 和 `FAIL` 不得进入可检索索引。
- 任何涉及 PHI 的远程链路默认拒绝明文 HTTP。
- 运行环境缺少 pytest/ruff 时，不得声称后端测试通过；必须记录验证限制。
