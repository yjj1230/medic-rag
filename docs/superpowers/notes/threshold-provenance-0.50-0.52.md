# 阈值 0.50 / 0.52 的数字是怎么来的——完整血统链

> 问题：`0.50` 和 `0.52` 这两个分数究竟从哪来？
> 结论先行：**两者来源完全不同。0.50 有完整实证链（但样本极小）；0.52 是四舍五入的产物，
> 没有任何实验直接产出过它。**

---

## 1. 一句话回答

| 数字 | 来源 | 性质 |
|---|---|---|
| **0.50** | 2026-09-24 标定：分离区间 `[0.4788, 0.5179]` 的**整数中点** `0.4983` 取整 | 有实证链，但是**取整值**；样本极小（18 用例 / 30 相关 + 62 不相关候选） |
| **0.52** | 我在 2026-09-29 对比实验里手选的"稍高一点"的档位 | **非标定产出**；仅因 `0.53` 已出现召回损失、`0.50→0.52` 是干净的 0.02 步长 |

---

## 2. 0.50 的血统链（五步）

### 第 1 步：发现 `vector_score` 不是余弦（§2.4）

`scripts/retrieval_gate_prototype.py` + `.workbuddy/space_type_probe.py` 实测：

```
knn_vector mapping 未声明 space_type → OpenSearch 默认 l2
```

用真实索引逐点拟合：

| id | OpenSearch `_score` | 真余弦 | `1/(1+L2²)` |
|---|---|---|---|
| 39f7ae94 | 0.55734 | 0.60288 | **0.55734** ✓ |
| 7498fde6 | 0.47583 | 0.44920 | **0.47583** ✓ |
| 217f6ad9 | 0.43986 | 0.36327 | **0.43986** ✓ |

→ `vector_score = 1/(1+L2²)`，L2 归一化下 `L2² = 2 − 2cos`，故：

```
l2_inv = 1/(3 − 2·cos)
```

### 第 2 步：收集两路候选的分数分布

来源文件：`eval_out/raw_score_probe.json`（`vector_cosine` 段）

| 组 | n | min | p50 | max | mean |
|---|--:|--:|--:|--:|--:|
| **gold（相关）** | 30 | **0.5346** | 0.6258 | 0.6724 | 0.6071 |
| **noise（不相关）** | 62 | 0.4073 | 0.4715 | **0.6403** | 0.4828 |

### 第 3 步：扫阈值找分离点

同文件的 `sweep` 数组（真余弦空间）：

| 阈值 | 拒答正确 | 可答命中率 |
|--:|:--:|--:|
| 0.41 ~ 0.43 | 0/2 | 1.000 |
| 0.44 ~ 0.45 | 1/2 | 1.000 |
| **0.46 ~ 0.53** | **2/2** | **1.000** |
| 0.55 | 2/2 | 0.9286 ← 开始掉 |
| 0.56 | 2/2 | 0.7857 |
| 0.63 | 2/2 | 0.3571 |

→ **可用区间是 `[0.46, 0.53]`**：低于 0.46 拒答不足，高于 0.53 命中率开始掉。

### 第 4 步：折算到 `l2_inv` 空间并取中点

分离区间的**真正边界**（spec §2.4 表）是：

| 真余弦 | l2_inv | 含义 |
|--:|--:|---|
| 0.4556 | **0.4788** | 不相关最大值 |
| 0.4951 | **0.4976** | **分离中点** |
| 0.5346 | **0.5179** | 相关最小值 |

```
中点 = (0.4788 + 0.5179) / 2 = 0.4983
```

### 第 5 步：取整 → **0.50**

> **关键洞察（spec §2.4 原话）**：
> *"0.5000 | 0.5000 | ← 巧合：两空间在 0.5 处数值相同"*
>
> 因为 `1/(3 − 2·0.5) = 0.5`。**0.50 在 l2_inv 与 cosinesimil 两个空间里数值恰好相等**
> —— 这是选 0.50 而非 0.4983 的真正理由：**它让阈值跨分数空间可移植**。

## 3. 0.52 的血统链（一步，且不来自标定）

我在 `scripts/retrieval_rejection_threshold_sweep.py` 里手写：

```python
THRESHOLD_LOW = 0.50
THRESHOLD_HIGH = 0.52
```

**选择 0.52 的理由**（当时）：

1. 0.50 是既有 spec 值，必须作为基准；
2. `raw_score_probe.json` 显示 0.53 已开始掉命中率 → 上限被 `0.53` 封住；
3. 在 `(0.50, 0.53)` 之间取整的 0.02 步长 → `0.52`。

→ **0.52 没有任何实验直接产出**。它不是扫出来的最优点，是"基准 + 上限之间取个整"的产物。
它之所以在 22 条评估集上表现更好（18/22 → 20/22），是因为**实测刚好证明它更优**，
但**它的选择过程本身是启发式的**。

## 4. 两个数字的可靠性对比

| 维度 | 0.50 | 0.52 |
|---|---|---|
| 实证链 | ✅ 完整（分布 → 扫描 → 分离区间 → 中点） | ❌ 无（启发式选点） |
| 验证样本 | 18 用例 / 30 相关 + 62 不相关候选 | 22 拒答 + 14 可答（我的新实验） |
| 空间可移植性 | ✅ 0.5 处两空间数值相同 | ⚠️ 仅绑定 `l2_inv` |
| 是否被后续推翻 | 否，理论依据成立 | 否，实测更优 |

**共同点：两者都只是"冷启动初值"** —— 09-24 spec §6.4 自己标注：
> *"这是冷启动初值。分离区间来自 30 条相关 + 62 条不相关候选、评估集仅 18 条用例。
> 必须在真实评测集上复核。"*

## 5. 一个必须指出的统计疑点（数据内部不一致）

`raw_score_probe.json` 的 `vector_cosine.noise` 报告 **`max = 0.6403`**，
但 spec §2.4 的分离表写 **"不相关最大值 = 0.4556"**。二者相差 0.185，**无法同时成立**。

**这个不一致会影响 0.4983 这个中点值吗？**

→ **不会，结论反而更稳健。** 推理：

分位交叉点独立于尾部样本：

- gold 的 `p50 = 0.6258`、`min = 0.5346`
- noise 的 `p50 = 0.4715`、`min = 0.4073`

**50% 分位差 = 0.6258 − 0.4715 = 0.1543**，分数分布是**清晰双峰分离**的。
少数高相似噪声（最多约 3/62 ≈ 5%）不改变主体分离结构。

**且这个不一致恰好被我的 22 条实验独立证实了方向**：
→ 我新构造的 `edge` 层用例 `bp-drug-choice` 拿到 **0.584**，
   确实落在"噪声也能窜高"的范围，但**它就是被 0.50/0.52 漏放的那一类**。

---

## 6. 实测补强：0.52 的"零代价"在严格口径下也成立

我原先报告写的"gold 零损失 14/14"用的是 **hit（命中）**口径——只要返回集中出现任意一条
gold 即算通过。**命中 ≠ 召回**：多 gold 用例即使只剩 1 条，hit 仍为真。

补测（`content_hash` 去重口径，与 `retrieval_cosine_gate_eval.py` 一致）：

| 指标 | @0.50 | @0.52 | Δ |
|---|--:|--:|--:|
| Hit@3 | 14/14 | 14/14 | 0 |
| **Recall@3 均值** | **0.9643** | **0.9643** | **0.0000** |

→ 唯一 recall < 1.0 的是 `priv-red-cell`（2 条去重 gold，只召回 1 条），
   且**两档完全相同**。**严格的召回口径下，0.52 依然零代价。**

## 7. 你现在应该怎么用这两个数字

1. **0.50 可以放进 artifact**，但它携带的是"18 用例标定"的血统 —— 必须在
   `eval_dataset_version` 字段里如实记下样本量。
2. **0.52 也可以放进 artifact**，但要明白它是**启发式选点 + 事后验证**，
   不能宣称"标定得出 0.52"。
3. **两个数字都不能当终点**：可分带宽只有 `0.483 ~ 0.535`（宽 0.052），
   而 `bp-drug-choice = 0.584` **高于全部 14 条可答用例**——
   **放弃"用单一阈值解决所有越界"，转向意图路由 / 证据充分性判定。**
