## 2. 根因①（超时死配置）—— 成立，但 120s 也不够

### 2.1 接线缺口（逐处核实）

| 位置 | 事实 |
|---|---|
| `.env` | `MODEL_REQUEST_TIMEOUT_SECONDS=120` |
| `core/config.py:54` | `model_request_timeout_seconds: float = 30.0`（字段存在） |
| `chat/prompts.py:31` | `build_chat_request()` **不接受** `timeout_seconds` 参数 |
| `models/contracts.py:30` | `ChatRequest.timeout_seconds: float = 30.0` |
| `api/composition.py:193-206` | **不传** `total_timeout_seconds` → 恒用默认 **60.0** |
| `chat/orchestrator.py:495` | `min(request.timeout_seconds, remaining)` → 实际按 30s 发请求 |

### 2.2 模型真实延迟（9 次实测，同一问题）

| 序 | 延迟 | 输出字符 | completion_tokens | finish |
|---|---|---|---|---|
| 1 | 35.4s | 757 | 1354 | stop |
| 2 | 70.0s | 899 | 2597 | stop |
| 3 | 52.2s | 732 | 2566 | stop |
| 4 | 32.2s | 1281 | — | stop |
| 5 | 99.2s | 1484 | — | stop |
| 6 | 77.6s | 1356 | — | stop |
| 7 | 67.7s | 1483 | — | stop |
| 8 | 18.0s | 1333 | — | stop |
| 9 | 55.6s | 1341 | — | stop |

**分布：18.0 – 99.2s，中位 ~55s，p100=99.2s。波动 5.5 倍。**

> ⚠️ **结论修正**：仅把 30s 改成 120s 是**必要的但不充分**——
> 120s 距实测 p100（99.2s）只余 21s 余量，网关再抖一次即越界。

## 3. 根因③（`max_output_tokens=1200` 截断）—— **证伪，应撤销**

实测 `completion_tokens` = **1354 / 2597 / 2566**，全部 `finish_reason="stop"`，
输出 1281–1785 字符。**网关未遵守 `max_completion_tokens=1200`。**

→ 旧报告"长回答被截断 ⇒ 引用不存在的 ID"的推断**不成立**。
输出中确实出现过"引用了不存在的证据"（见 §4.2 A 组），但原因是**标记格式未被解析**，
不是截断。

## 4. 根因②（引用校验不兼容）—— 成立，但是**三个独立子缺陷**

旧报告描述为"模型按段落级标注，校验器要求句末"，**不准确**。实测模型确实逐句标注。

### 4.1 子缺陷 (a)：提示词占位符歧义 → 模型产出 `[evidence: <uuid>]`

`SYSTEM_PROMPT` 写的是「格式如 `[evidence-id]`」。模型把一个**占位符**理解成字面内容，
产出：

```
… 确诊需由医生结合多次测量和临床情况来判断 [evidence: 7498fde6-ae5e-4af3-9bf9-bcdf5fef5226]。
```

而校验器正则 `\[([A-Za-z0-9_:\-]+)\]` **不允许空格** → `extract_ids()` 返回 **0 个 ID**
→ `validate()` 先报"回答缺少证据引用"/"引用了不存在的证据"。

**实测复现**：一次真实调用中 11 个标记**全部**是该形态。

### 4.2 子缺陷 (b)：Markdown 结构行被当作医学断言句

`_check_sentence_citations` 把 `## 标题` 也当作待检查句。实测 A 组 8 处失败中
**4 处是标题/列表符号行**：

```
'**关于您报告的血压读数**'
'**在家自测血压的注意事项**'
'- 饮食上，减少钠盐摄入是控制血压的基础措施之一，建议每日食盐不超过 5 克…'
```

同类问题也发生在段落级：`_MIN_PARAGRAPH_CHARS_REQUIRING_CITATION = 30` 会把
`'## 生活方式方面（以下为公共健康教育知识，并非针对您个人的处方）'`（**33 字符**）
判为"缺引用的段落"。

### 4.3 子缺陷 (c)：否定/免责句豁免不完整 → 假阳性

实测 B 组残留的"真断言缺引用"中：

```
'需要先说明：单次家庭测量的数值如何解读，我无法据此作出判断或诊断。'
```

这是**明确的免责句**，却未被任何豁免规则覆盖：
- `is_negated_assertion()` 要求同时命中否定词 + **断言动词**（`_ASSERT_VERB`），
  本句无断言动词 → 不豁免；
- `_DISCLAIMER_SENTENCE` 的关键词表（`咨询|就诊|…|医生判断|…`）不含"无法判断/无法据此"。

### 4.4 A/B 对照：**强化提示词是主线，且零安全代价**

| 指标 | A-现行提示词 | B-强化提示词 |
|---|---|---|
| 含 `evidence` 字样的变异标记 | **11** | **0** |
| 段落级缺失 | 0 | 0 |
| 句级失败（非结构行） | **8** | **2** |
| E2E `validate` | FAIL（引用了不存在的证据） | FAIL（句级） |

强化版只做了三件事（**不放松任何校验规则**）：
1. 明确"**每一句**结论都要各自标注，不能只在段落末尾标一次"（并给示例）；
2. 显式说明"Markdown 标题行、纯列表符号行不需要标注引用"；
3. 明确"证据 ID **直接使用**方括号中的内容，不要加 `evidence:` 等前缀"。

→ **子缺陷 (a) 被提示词修复（11→0）**；结构行约定写进提示词后仍有残留，
说明 **(b) 需在校验器侧修正**（提示词不能 100% 约束输出形态）。

## 5. 附带发现（此前未记录）

| # | 发现 | 影响 |
|---|---|---|
| N1 | `Evidence.id` 是 **完整 UUID**（36 字符），模型须逐字复制 | 标注成本高、易错；是子缺陷 (a) 的土壤 |
| N2 | 前端 `MessageBubble.vue:27-34` 只做 HTML 转义，**不渲染/隐藏引用标记** | 长 UUID 原样展示给患者，可读性差（独立任务） |
| N3 | `_check_paragraph_coverage` 与 `_check_sentence_citations` 的"结构行"盲区同源 | 应在同一处修正，避免两套口径 |
| N4 | 段落阈值按**原始字符数**计（含 `##`、`**` 等记号） | 标题易被误判为"需引用的段落" |
