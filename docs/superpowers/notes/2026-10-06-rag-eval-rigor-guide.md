# RAG 评测的专业化：五环节方法

> **文档定位**：不是"指标清单"，而是"指标可信度的生产流程"。
> **与既有文档的关系**：
> - `docs/RAG评估体系设计方案.md` —— 本项目的**指标落地版**（对接 `QualityGate` / `evaluate_retrieval` 等代码）；
> - `docs/RAG评估入门指南.md` —— **通用入门版**（补齐生成质量维度与工具选型）；
> - **本文** —— **可信度方法论**：补齐前两份文档都缺失的「统计显著性」环节，并把"评什么"升级为"凭什么信"。
>
> **核心论断**：指标列全只是及格线。RAG 系统是唯一一个"检索错"与"生成错"表现为同一症状（答得不对）的系统，因此只看端到端准确率永远无法归因；而只看分层指标、不做统计处理，则会把噪声当成结论。**专业评测 = 真实数据集 + 真实链路 + 正确口径 + 统计显著性 + 分层门禁。**
>
> 撰写日期：2026-10-06

## 0. 一页速览

### 0.1 五环节流水线

```
① 数据集治理  ──►  ② 真实链路执行  ──►  ③ 指标计算口径  ──►  ④ 统计显著性  ──►  ⑤ 分层门禁
   评什么            怎么跑                怎么算              差异是真的吗        怎么卡
   ↑ 决定上限        ↑ 决定有效性          ↑ 决定可比性        ↑ 决定结论强度      ↑ 决定上线与否
```

**每一步都在为下一步的可信度兜底**——任一环节塌陷，后面的数字全部作废。

| 环节 | 一句话职责 | 缺失后果 |
|---|---|---|
| ① 数据集治理 | 样本量、分层、gold 完整度、负样本 | 指标达标但统计置信度不足 |
| ② 真实链路执行 | 走生产路径，不模拟、不跳过 | **CI 绿灯与质量无因果关系** |
| ③ 指标计算口径 | 去重、分母可及性、分档、分数空间 | 数字虚高或误判达标 |
| ④ 统计显著性 | 置信区间、配对检验、样本量 | **把噪声当结论** |
| ⑤ 分层门禁 | 零容忍 / 回归 / 绝对目标三分法 | 门禁形同虚设或频繁误报 |

### 0.2 本项目现状判定

| 环节 | 状态 | 依据 |
|---|---|---|
| ① 数据集治理 | 🟡 **部分具备** | 18 条用例 / 12 条语料；每条 query 仅 1 个 gold；无负样本集 |
| ② 真实链路执行 | ✅ **已做对** | `scripts/retrieval_tuning_lab.py` 真调 `retrieve` + 显式 `k=top_k` |
| ③ 指标计算口径 | 🟡 **已做对但缺两项** | 双口径去重已做；缺 MAP@K / 证据充分率口径 |
| ④ 统计显著性 | ❌ **完全缺失** | 所有"达标/优于"结论均无置信区间或显著性检验 |
| ⑤ 分层门禁 | 🟡 **框架完整、基线未重算** | `release_gate` 已在；但 `baseline.json` 出自旧版模拟检索 |

**结论：最稀缺、投入产出比最高的是第 ④ 环。**

## 1. 环节一 · 数据集治理

### 1.1 四类数据集必须物理分离

| 数据集 | 用途 | 更新频率 | 是否门禁 |
|---|---|---|---|
| **dev set** | 快速迭代、调参、调试 | 随需增补 | 否 |
| **test set（封存）** | 上线门禁，**绝不用于调参** | 季度重标，版本冻结 | **是** |
| **regression set（合成 fixture）** | 解析/分块逻辑回归 | 随代码变更 | 是（本地/CI） |
| **shadow set（线上采样）** | 真实分布监控、主动学习 | 持续 | 否（监控告警） |

**红线**：任何一次迭代都不得在 test set 上调参后直接上线——否则门禁失去意义。评测集必须带 `eval_dataset_version`，与 `CalibrationArtifact.eval_dataset_version` 绑定。

> **本项目的现实违规**：22 条拒答评估集既用于 **0.50 vs 0.52 的选型**，又用于**验收**。严格说已经被调参污染。补救方式是至少把 `edge` 层那 5 条单独封存，不再参与任何阈值选择。

### 1.2 标注要素（最小必要集）

**文档级**：`gold_blocks`（关键段落定位）、`expected_anchors`（页码 / sheet / range）。
**query 级**：`gold_evidence_ids`（相关证据）、`required_evidence_ids`（回答该问题的最小充分集）、`forbidden_evidence_ids`（同义干扰项，用来测噪声）。

标注成本必须分层控制（本项目 `RAG评估体系设计方案.md §0.2` 的 A/B/C 三分类）：

| 类别 | 含义 | 成本 | 占比目标 |
|---|---|---|---|
| **A · 全自动** | 纯统计口径，从代码/索引/日志直接算出 | 零 | ~60% |
| **B · 弱监督半自动** | 少量人工种子，其余靠规则/模型自举 | 低 | ~25% |
| **C · 必须人工标注** | 语义真值（相关性、充分性） | 高 | ~15% |

**原则：能用 A 类解决的绝不引入 B/C。** C 类标注只用于「校准 A/B 类代理指标」与「守住门禁关键真值」，不做全量标注。

### 1.3 分层抽样（宁要 100 条覆盖 5 类，不要 500 条同一类）

按三个维度分层，每格至少 5 例：

| 维度 | 分层值 |
|---|---|
| 文档类型 | PDF 原生 / 扫描件 / DOCX / XLSX |
| query 类型 | 事实型 / 数值型 / 趋势型 / 是否型 |
| 难度 | 易 / 中 / 难（库内覆盖 / 相邻病种 / 含病名但库内不覆盖） |

**均值会骗人**：整体 0.85 可能是"易题 0.98 + 难题 0.30"平均出来的。分档报告不是可选项，是必需品。

### 1.4 样本量（决定你能下什么结论）

| 用途 | 样本量 | 说明 |
|---|---|---|
| 冒烟 / 快速迭代 | 20–50 条 | 能发现大问题，**不能做统计结论** |
| 稳定评测 / 回归门禁 | 100–300 条 | 指标波动可接受，推荐起步规模 |
| 上线验收 | 300–500 条 | 分层覆盖各类型与难度 |
| A/B 显著性判断 | 每侧 ≥200 条 | 小样本差异可能只是噪声 |

> 本项目的 18 条用例落在"冒烟"档，**远低于任何可下结论的门槛**。

### 1.5 负样本集（零容忍项的前提）

零容忍指标（越权 / 删除残留 / 复核泄漏）当前报告为 0，但**只能证明"过滤逻辑没有误伤正常数据"，不能证明"残留会被拦住"**——因为语料里根本不存在该被过滤的记录。

**唯一补法**：构造负样本集——主动插入 `deleted=true` 与 `retrieval_eligible=false` 的记录，验证它们确实不出现在 Top-K 中。

在此之前，这两项应标注为 **UNKNOWN（未验证）**，而非 PASS。**"测不出非零"不等于"为零"。**

### 1.6 本项目现状

| 问题 | 现状 | 后果 |
|---|---|---|
| 样本量 | 18 条用例 / 12 条语料 | 远低于 50–100 条要求 |
| gold 数 | **每条 query 只标 1 个** | P@3 理论上界 = 1/3 |
| 分层 | 仅 quality/rejection/safety 三类 | 无难度分层 |
| 负样本 | 无 | 两项零容忍**假绿** |

## 2. 环节二 · 真实链路执行

### 2.1 四条铁律

1. **真调生产入口。** 评估执行器必须调用 `RetrievalService.retrieve`，真命中 OpenSearch 的 public/private 索引。
2. **显式传 `k=top_k`。** `evaluate_retrieval` 的 `k` 默认取传入列表长度——不传会让"把所有候选都返回"的配置获得虚高召回率。
3. **gold 来自真实索引 ID。** 人工勘察真实索引后判定的文档 ID，不是合成占位符。
4. **不可达时显式失败，不静默跳过。** OpenSearch / 模型网关不可达 → 直接抛错退出，不产出"全绿"报告。

第 4 条是专业与业余的分界：**一个"跳过测试后显示全绿"的评估器，比没有评估器更危险。**

### 2.2 反模式：模拟检索

本项目 `src/medical_rag/eval/golden.py:524` 的 `_rag_metrics_for_fixture` 按阅读顺序全量返回分块：

```python
# 模拟检索：产出的分块按阅读顺序排序（全部参与），因此 K == len(produced)
produced = [_stable_chunk_anchor(chunk) for chunk in chunks]
returned = list(dict.fromkeys(produced))
```

**后果**：`gold_anchors ⊆ returned` 恒成立 → `recall/MRR` **数学必然为 1.0**。CI 一直是绿的，但它与检索质量**没有任何因果关系**。

这就是「**评估空转**」：框架完备、执行正常、数字漂亮，唯一的问题是数字没有意义。

### 2.3 正确的执行形态

以本项目 `scripts/retrieval_tuning_lab.py` 为范本：

```python
# 真实检索：每个用例都真实调用生产服务
result = service.retrieve(query, context)
returned = [item.id for item in result.items]

# 显式传 k=top_k：不传会让 k 取返回列表长度，召回率虚高
raw = evaluate_retrieval(evaluation, returned, k=cfg.top_k)
```

以及 `scripts/chat_e2e_acceptance.py` 的失败策略：

```python
try:
    version = client.info()["version"]["number"]
except Exception as exc:
    raise RuntimeError(f"OpenSearch 不可达，验收无法进行（不静默跳过）: {exc}") from exc
```

### 2.4 本项目现状

| 项 | 状态 |
|---|---|
| `retrieval_tuning_lab.py` | ✅ 真链路 + 显式 k + 真 gold ID |
| `chat_e2e_acceptance.py` | ✅ 真链路 + 不可达即失败 |
| `eval/golden.py` | ❌ 模拟检索（CI 门禁仍基于它） |
| `tests/eval/` | ❌ 无任何真实 `retrieve` 调用 |

**行动**：把 `eval/golden.py:_rag_metrics_for_fixture` 的模拟检索替换为真实调用，这是让 recall/MRR 从"数学必然的 1.0"变为"真实测量值"的**唯一关键改动**。

## 3. 环节三 · 指标计算口径

### 3.1 去重口径（必须双口径并列）

同一文档切成多个 chunk、或同一内容被反复上传，命中会虚高。

**本项目实测**：私有库 7 条记录仅 3 组唯一内容（组大小 `[4, 2, 1]`）——4 条记录 `content_hash` 相同、文本完全一致。按索引 ID 计算召回率是假的。

正确做法：排序指标同时给出 `raw`（按索引 ID）与 `dedup`（按 `content_hash` 归组）两种口径，**以后者为准**。

```python
def _dedup_key(content_hash_by_id, record_id):
    digest = content_hash_by_id.get(record_id)
    return f"h:{digest[:12]}" if digest else f"id:{record_id}"
```

**Hit ≠ Recall 的补充提醒**：本项目 `priv-red-cell` 的 `Hit Rate = 1.0` 但 `Recall@3 = 0.5`（2 条 gold 只召回 1 条）。只报 Hit Rate 会让这个缺陷隐身。

### 3.2 分母可及性（看到"不达标"先算数学上界）

有一类指标的分母天然不可达，必须先行检查：

| 指标 | 不可达条件 | 数学上界 |
|---|---|---|
| **P@K** | `|gold| < K` | `min(1, |gold|/K)` |
| Recall@K | 通常可达 | — |
| MAP@K | gold 集过小时不稳定 | — |

**本项目实例**：评估集每条 query 只标 **1 个** gold，而 K=3 →

```
P@3 的理论上界 = min(1, 1/3) = 0.333
实测 P@3      = 0.333     ← 恰好等于上界
```

也就是说，**检索一条 gold 都没丢**，"不达标"完全是阈值假设了 gold 集大小为 2~3 条（P@3 ≥ 0.70 需 ≥2.1 条 gold）。

**两个修法（择一）**：
- **(a) 补标注**：每条 query 标 2~3 条相关证据；
- **(b) 改口径**：对小 gold 集场景改用 **MAP@K / 证据充分率**，这两个不受 `|gold|/K` 上界限制。

> ⚠️ **不要为了让指标变绿而调低阈值**——那是 Goodhart 化。应改标注口径。

### 3.3 分档报告

至少要按以下维度切开，只报总均值等于埋雷：

- `scope`（public / private）
- `category`（quality / rejection / safety）
- 难度档（易 / 中 / 难）
- `file_type` / `parser_version` / `chunker_version`（定位是哪类文档拖低整体）

### 3.4 分数空间必须与阈值成对声明

**本项目最"专业"的一处，也是最容易踩的一处**：

`vector_score` **不是余弦相似度**，而是 `1/(1+L2²)`——因为 kNN 查询未声明 `space_type`，OpenSearch 默认用 l2。在 L2 归一化向量下：

```
l2_inv = 1/(3 − 2·cos)   ↔   cos = (3 − 1/s)/2
```

这是余弦的**严格单调变换** → 排序等价、数值不同 → **任何阈值都必须连 `score_space` 一起声明**，否则跨版本不可比。

> **本项目教训**：曾误用错误换算 `1/(2−cos)` 下过结论，后被撤销。根因就是把"数值"当成了"语义"。

### 3.5 报告模板（字段清单）

每份评测报告至少包含：

| 字段 | 为什么 |
|---|---|
| `eval_dataset_version` | 数据集可追溯 |
| `index_version`（public / private 各一） | 语料可追溯 |
| `embedding_model` + `dimensions` | 向量化身份 |
| `score_space` | 阈值可比性（见 §3.4） |
| `k` 的显式取值 | 指标可比性 |
| `dedup` 口径标记 | 去重方式 |
| **`ci95_low` / `ci95_high`** | **统计显著性（见 §4）** |
| 样本量 `n` | 结论适用范围 |
| 原始 JSON 路径 + 脚本路径 | 可复现 |

## 4. 环节四 · 统计显著性

### 4.1 为什么这是专业与业余的分水岭

绝大多数团队不做这一步，于是会出现这样的结论：

> "阈值 0.52 严格优于 0.50（20/22 vs 18/22），零代价可上线。"

这句话在**统计上站得住吗？** 需要用两步检验：先看置信区间是否与基线重叠，再看配对差异是否显著。

### 4.2 先选对方法：二值用 Wilson，连续量用 t

**这步不能错**——用错方法会得出错误区间（本文初稿即犯过，见 §4.2.3 修正记录）。

| 指标类型 | 每用例产出 | 正确方法 | 公式 |
|---|---|---|---|
| **Hit Rate / 拒答正确率 / 越权命中率** | 0 或 1（二值） | **Wilson score 区间** | 见 §4.2.1 |
| **Recall@K / MRR / nDCG@K** | 连续值 ∈ [0,1] | **t 区间**（样本均值） | `x̄ ± t_{α/2,n−1}·s/√n` |

**为什么 Recall@K 不能用 Wilson**：每个用例的 Recall 可能是 0.5、0.667 这样的**连续值**（如 `priv-red-cell` 的 2 条 gold 只召回 1 条 → 0.5）。Wilson 的输入是 `successes / trials` 整数对，套不上去。

#### 4.2.1 二值指标（Wilson）：本项目实例

| 情形 | 95% Wilson 区间 | 半宽 |
|---|---|---|
| 拒答正确 **2/2** | [0.342, 1.000] | ±0.329 |
| 拒答正确 13/14 | [0.685, 0.987] | ±0.151 |
| 拒答正确 14/14 | [0.785, 1.000] | ±0.108 |
| 拒答正确 289/300 | [0.936, 0.979] | ±0.022 |

**读法**：`2/2` 看似"100% 拒答正确"，但区间下界只有 **0.342** —— 真实能力可能低到 34%。这就是小样本下"满分"的真相。

#### 4.2.2 连续量（t 区间）：`Recall@3` 的实测区间

本项目 `Recall@3 = 0.9643`，逐用例明细为 **13 个 1.0 + 1 个 0.5**（`priv-red-cell`）：

```
mean  x̄ = 0.9643
sd    s  = 0.1336
se       = s/√14 = 0.0357
t_{0.975,13} = 2.1604        （n<30 必须用 t，不能用 z=1.96）
半宽  h  = 2.1604 × 0.0357 = 0.0772
区间      = [0.887, 1.041]  → 按比例边界截断为 [0.887, 1.000]
```

| 样本量 | 95% t 区间 | 半宽 | 与 0.90 阈值的关系 |
|---|---|---|---|
| **n=14**（现状） | **[0.887, 1.000]** | ±0.077 | ⚠️ **下界 0.887 < 0.90，无法确认达标** |
| n=300（目标） | ≈ [0.949, 0.979] | ±0.015 | ✅ 可确认 |

**读法**：n=14 时区间下界 **0.887 低于稳定期阈值 0.90**。虽然点估计 0.964 看起来"超稳定期达标"（`指标达标核对表.md` 即如此判定），但真实能力完全可能只有 0.89 —— **该判定在统计上不成立**。

> **t vs z 的差别不可忽略**：n=14 时 `t=2.160` vs `z=1.960`，半宽相差 **10%**。用小样本的 z 会系统性低估不确定性——这正是"0.964 达标"这类结论的成因。

> **操作准则：n<30 时只报区间，不报"达标/未达标"。**

#### 4.2.3 修正记录（2026-10-06）

本文初稿曾给出 `Recall@3` 的区间为 `[0.785, 1.000]`（±0.108）—— **该数字错误**，已更正为 `[0.887, 1.000]`（±0.077）。

| | 错误值 | 正确值 | 根因 |
|---|---|---|---|
| 区间 | [0.785, 1.000] | [0.887, 1.000] | 把 `Wilson(14,14)` 的下界当成了 `Recall@3` 的区间 |
| 方法 | Wilson | **t 区间** | Recall@K 是连续量，不是二值比例 |
| 半宽 | ±0.108 | ±0.077 | 上述两者的合成结果 |

**结论方向未变**（n=14 仍不足以确认达标），但**数值差 0.098，足以改变 0.887 与 0.785 这种量级的判断**。这一条本身就是"每个数字可追溯"的实例：任何区间都必须连同**方法名**（Wilson / t）与**原始逐用例列表**一起给出，否则无法复核。

### 4.3 配对显著性检验（McNemar）

同一批 query 上对比两档阈值，是**配对**设计，必须用配对检验（检验力远高于独立两样本）。

**McNemar 检验结构**：

| | 阈值 A 通过 | 阈值 A 不通过 |
|---|---|---|
| **阈值 B 通过** | a（都通过） | **b（B 好，A 差）** |
| **阈值 B 不通过** | **c（A 好，B 差）** | d（都不通过） |

只看不一致格 `b` 与 `c`。精确检验：`b ~ Binomial(b+c, 0.5)`。

**本项目实例**：`0.52` 相对 `0.50` 多答对 2 条，且无回退 → `b=2, c=0`：

| b（c=0） | 精确双尾 p | 判定（α=0.05） |
|---|---|---|
| **2** | **0.5000** | ❌ 无法与噪声区分 |
| 3 | 0.2500 | ❌ |
| 4 | 0.1250 | ❌ |
| 5 | 0.0625 | ❌ 临界 |
| **6** | **0.0312** | ✅ 显著 |
| 7 | 0.0156 | ✅ |

**结论**：
- `0.52 优于 0.50` 目前只是**方向性建议**，不是统计结论——它需要 **≥6 条**翻转样本才能通过显著性检验；
- 而且 `0.50` 是 09-24 冷启动定的初值，`0.52` 是在 `0.50` 与 `0.53` 之间取整的**手选值**——**两个都还没有资格当门禁阈值**；
- 可分带宽仅 `0.483~0.535`（宽 **0.052**，语料贫所致）。在这么窄的带宽上做阈值调优，本质上是在**拟合噪声**。

> 这正好从统计上印证了 `阈值血统` 文档的既有判断：**"纯阈值非终解，需意图路由 / 证据充分性判定补刀。"**

### 4.4 样本量核算

要检出 `δ` 的差异（α=0.05 双尾，power=0.80），配对二值设计的样本量：

```
n = (z_{α/2} + z_β)² · (π_d − δ²) / δ²
```

其中 `π_d` = 两方案的**不一致率**（McNemar 的 discordant 比例）。

| 目标差异 δ | π_d = 0.10 | π_d = 0.20 | π_d = 0.30 |
|---|---|---|---|
| **0.05** | ≈ 310 | ≈ 620 | ≈ 930 |
| **0.10** | ≈ 75 | ≈ 150 | ≈ 230 |

**对照**：若误用独立两比例检验（左尾朴素算法），检出 `0.90 vs 0.95` 需**每侧 435 条**——虽更保守，但没利用配对结构，代价高。

**实务建议**：分辨率 0.05 的阈值调优，规划 **300~600 条配对样本**；分辨率 0.10 则 100~250 条即可。

### 4.5 判断强度准则（三类硬度 × 样本量门槛）

不同指标该用不同判断逻辑，混用必然误判：

| 指标类型 | 判断强度 | 依据 | 样本量门槛 |
|---|---|---|---|
| **零容忍安全项** | **绝对**：非零即否决 | 计数型，无统计不确定性 | 无（但**必须真跑负样本**） |
| **确定性工程项**（延迟分位、成本） | **阈值 + 容忍倍数** | 受墙钟噪声影响，但不能放松 | 无（分位数收敛快） |
| **质量项**（Recall/MRR/nDCG） | **配对检验 + 置信区间** | 这是唯一诚实的做法 | **n≥100 才收紧阈值** |

**配套方法选择表**（易错点，务必对照）：

| 指标 | 逐用例产出 | 用哪种区间 | 不能用 |
|---|---|---|---|
| Hit Rate / 拒答正确率 / 越权率 | 0 或 1 | **Wilson** | t（二值方差被高估） |
| Recall@K / MRR / nDCG@K / P@K | 连续 ∈ [0,1] | **t 区间** | Wilson（输入形状不匹配） |
| 延迟 P95 | 连续毫秒 | 分位数法 / bootstrap | 均值 t 区间（分布长尾） |

**两条配套习惯**：
1. **配对而非独立**：同一批 query 上对比两套配置，用 McNemar（离散）或配对 t / bootstrap（连续）。
2. **区间优先**：先报区间，区间不重叠再谈显著性；区间重叠时即使均值更高也应表述为"未观测到显著差异"。
3. **连方法一起报**：`Recall@3 = 0.964 [0.887, 1.000], t区间, n=14` —— 缺方法名或样本量则无法复核（见 §4.2.3 修正记录）。

### 4.6 常见误用

| 误用 | 表现 | 后果 |
|---|---|---|
| 报告点估计不报区间 | "Recall@3 = 0.964，达标" | 掩盖真实不确定性 |
| 用独立检验做配对比较 | 检验力大幅下降 | 真差异被判成不显著 |
| n<30 下"达标/未达标"判定 | 18 条用例就宣布 M3 达成 | **虚假结论** |
| 在噪声带宽内调参 | 0.052 带宽上调阈值 | 拟合噪声，泛化差 |
| 只比均值不看翻转分布 | "20/22 vs 18/22 更好" | 忽略 b/c 结构，无法算显著性 |

### 4.7 一个反直觉的自检

> **如果某个指标长期是 1.00 或 0.00，几乎可以肯定测法有问题**（测试集太简单、或口径错误），而不是系统完美或崩溃。

真实系统的指标应落在中间区间**且有波动**。本项目 `Hit Rate = 1.000` 这类"满分"数字，配合 n=14 的样本量，恰恰是**最需要怀疑**的对象——`拒答正确率 = 2/2` 的 95% 区间下界只有 **0.342**（§4.2.1）。

**量化自检**：点估计接近 0 或 1 时，**区间几乎完全由 n 决定**：

| 观测 | n=14 | n=300 |
|---|---|---|
| 满分（k=n） | 下界 **0.785** | 下界 0.987 |
| 零分（k=0） | 上界 **0.215** | 上界 0.013 |

即：n=14 时"满分"仍可能是 0.79 的真实能力；n=300 时才敢说"确实接近完美"。

## 5. 环节五 · 分层门禁

### 5.1 三类硬度（不可混用）

| 类型 | 逻辑 | 适用 | 本项目实例 | 执行注意 |
|---|---|---|---|---|
| **零容忍** | 任一非零 → **无条件失败** | 安全、合规 | 越权 / 删除残留 / 复核泄漏 | **必须真跑负样本**，否则假绿 |
| **回归门禁** | 不得低于已冻结基线 | 质量指标 | `release_gate` 比较 `baseline.json` | 基线必须是**真实检索**产物 |
| **绝对目标** | 达到某数值才通过 | 交付验收 | 端到端任务成功率 | 只在**验收**用，不进 CI |

**噪声容忍**：延迟这类墙钟指标天然抖动，门禁应容忍合理倍数而非精确相等。本项目 `P95_REGRESSION_FACTOR = 3.0` —— 该设计正确，避免被时钟噪声反复误报。

### 5.2 基线必须本身真实

`release_gate` 会把新运行与已存 `baseline.json` 比较。但**基线自身也要走环节二**：

> **若 `baseline.json` 是用旧版模拟检索生成的，那所有质量项门禁都是空的。**

这是本项目 M4 里程碑之前**必须补的一步**。

### 5.3 门禁执行纪律

- **test set 封存**：绝不在 test set 上调参后再上线（见 §1.1）。
- **评估集版本化**：`eval_dataset_version` 与 `CalibrationArtifact` 绑定，模型/语料变更即失效重标。
- **每个数字可追溯**：报告里的每个指标要能指到"哪条脚本、哪个版本、哪次运行的原始 JSON"。
- **降级路径也要验**：外部依赖不可用时的行为必须验证（本项目已有实例：向量路径不可用时跳过门禁 → 系统"永不拒答"，该状态必须告警）。

### 5.4 门禁逻辑（本项目已有实现）

`src/medical_rag/eval/golden.py:release_gate` 已实现三层判定，顺序与强度正确：

```python
# 1) 安全：当前运行中任何非零违规一律让门控失败（无条件）
if current.permission_violations > 0:
    reasons.append(f"permission_violations_nonzero:{current.permission_violations}")
if current.deletion_residuals > 0:
    reasons.append(f"deletion_residuals_nonzero:{current.deletion_residuals}")

# 2) 质量：与已存基线比较，下降即失败
for key in ("chunk_recall_at_k", "mrr", "citation_accuracy"):
    if float(getattr(current, key)) < float(getattr(baseline, key)):
        reasons.append(f"{key}:current=...<baseline=...")

# 3) 延迟：容忍 3× 抖动，捕获严重回退
if baseline.p95_latency_ms > 0 and current.p95_latency_ms > baseline.p95_latency_ms * P95_REGRESSION_FACTOR:
    reasons.append(f"p95_latency_ms:...")
```

**待补**：质量项的回归门禁应增加**统计缓冲**——直接用点估计比较会让噪声触发误报（例如真实能力 0.95，某次测出 0.94 就 blocking）。建议改为"低于基线 − 置信区间半宽"才失败，或要求连续 N 次低于基线。

## 6. 归因方法（指标下降时怎么定位）

指标只是信号，归因才是目的。按以下顺序定位：

```
① 先查安全项
   越权 / 删除 / 复核泄漏非零 → 权限链路问题，与排序无关，优先级最高

② 再查构建层
   若「可检索率」下降、或某 file_type 的文本覆盖率下降
   → 是内容没进库，不是检索变差

③ 对比分档指标
   按 file_type / parser_version / chunker_version 切分
   → 定位是哪类文档拖低整体

④ 最后查检索层（gold 已进库前提下）
   Hit 高 但 nDCG/MRR 低  → 排序问题
   Hit 也低               → 召回问题（候选生成 / 门禁阈值）

⑤ 门禁诊断
   检查 diagnostics.gate_policy 是否为 TOP_K（未校准）
   → 未校准时 top_k 截断会被误读为低召回
```

**关键分辨**：`Hit 高但排序差` 与 `Hit 低` 是完全不同的问题，前者调 reranker，后者调候选生成或门禁。

## 9. 一句话总结

> **指标列全只是及格线。**
> 专业评测 = **真实数据集**（样本量 + 分层 + 完整 gold + 负样本）
> ＋ **真实链路**（不模拟、不跳过、显式 k）
> ＋ **正确口径**（去重、分母可及性、分数空间）
> ＋ **统计显著性**（区间 + 配对检验 + 样本量）
> ＋ **分层门禁**（零容忍 / 回归 / 绝对目标三分法）。
>
> 本项目在五条上分别处于「部分具备 / 已做对 / 已做对但缺两项 / **完全缺失** / 框架完整但基线未重算」
> —— 缺的正是第 ④ 环，而它恰好是投入产出比最高、也最能体现专业度的一环。

**最终自检三问**（任何指标取值前先答）：

1. 它走**真实链路**吗？
2. 它的**分母标全**了吗？
3. 它**去重**了吗？

三问都过，再谈数字高低。
