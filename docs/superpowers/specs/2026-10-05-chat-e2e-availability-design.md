# chat 端到端可用性修复 —— 设计规格（spec）

> 日期：2026-10-05
> 关联：`docs/chat链路启动诊断报告-2026-09-29.md`（旧根因结论，本 spec 修正其三处）、
> `docs/superpowers/notes/2026-10-05-p0-5-reproduction-and-rootcause.md`（实测证据）
> 状态：**待批准**（遵循 `FEATURE-WORKFLOW.md` spec + plan before code）
> 范围：让 `/v1/chat/answers` 在**真实模型 + 真实语料**下产出可用回答，而非稳定 `degraded`

---

## 1. 问题陈述

拒答能力已于 2026-10-05 启用（门禁 `cosine_absolute`），检索层可用。
但 **chat 端到端在真实链路下必然降级**，患者永远拿不到回答。

实测（生产配置、一次真实调用）：

```
[ret] gate_policy=cosine_absolute items=8 reason=None      ← 检索正常
[req] timeout_seconds=30.0                                  ← 生产实际用 30s
[FAIL-MODEL] ModelTimeout after 30.0s -> degraded
```

即使把超时放大到足够，仍会卡在引用校验（A/B 实测 E2E `validate` 全 FAIL）。

---

## 2. 根因（已实测修正，见证据报告）

| # | 根因 | 性质 | 是否涉及医学安全规则 |
|---|---|---|---|
| ① | `.env` 的 `MODEL_REQUEST_TIMEOUT_SECONDS` 是**死配置**；生产链路用 `ChatRequest` 默认 30.0s；`total_timeout_seconds` 亦非来自配置（恒 60.0） | 接线缺陷 | 否 |
| ②a | 提示词占位符 `[evidence-id]` 有歧义 → 模型产出 `[evidence: <uuid>]`（含空格）→ 校验器正则**解析出 0 个 ID** | 提示词缺陷 | 否（但影响校验有效性） |
| ②b | 校验器把 **Markdown 结构行**（`## 标题`、`- 列表符号`）当作待检查断言句；段落阈值按含记号的原始字符数计 | 分类缺陷（假阳性） | **是**（放松需明确边界） |
| ②c | 免责句豁免不完全：`'我无法据此作出判断或诊断。'` 无断言动词 → 不被 `is_negated_assertion` 覆盖，也不在 `_DISCLAIMER_SENTENCE` 词表内 | 分类缺陷（假阳性） | **是** |
| ③ | ~~`max_output_tokens=1200` 截断~~ | **已证伪，撤销** | — |

## 3. 目标与非目标

### 3.1 目标

| # | 目标 | 可验证判据 |
|---|---|---|
| G1 | 生产超时配置真正生效 | `ChatRequest.timeout_seconds` == `settings.model_request_timeout_seconds`；`total_timeout_seconds` 来自配置 |
| G2 | 端到端预算足以覆盖实测延迟 | `total_timeout_seconds ≥ model_request_timeout_seconds ≥ 120`，且满足 `≥ 实测 p100(99.2s) × 1.2` |
| G3 | 引用标记解析对真实输出稳健 | 对 `[<uuid>]` 与 `[evidence: <uuid>]` **两种形态**都能解析出正确 ID 集合 |
| G4 | 结构行不再被当作医学断言 | 纯 Markdown 标题/列表符号行不参与句级与段落级引用检查 |
| G5 | 免责/否定句豁免覆盖"无法判断"类表述 | 实测样本 `'…我无法据此作出判断或诊断。'` 不再触发失败 |
| G6 | **不放松任何医学安全约束** | 见 §5 负样本表：逐条必须仍然失败 |

### 3.2 非目标（明确不做）

- ❌ 不新增 `/metrics` 端点（独立重构，见 D17 结论）
- ❌ 不重构 `CitationValidator` 为"语义一致性"校验（那属 P0-4 评估体系职责）
- ❌ 不修 `max_output_tokens`（已被证伪，不是问题）
- ❌ 不在本 spec 处理证据 ID 缩短 / 前端引用渲染（N1/N2，独立任务）
- ❌ 不放宽"数值必须能在被引证据中定位"（`_check_numeric_consistency` 不动）
- ❌ 不放宽"不允许诊断性结论"（`_check_high_risk_claims` 不动）

## 4. 设计

### 4.1 根因①：超时接线

**D-A1 超时来源单一化。** `build_chat_request()` 新增 keyword-only 参数
`timeout_seconds: float | None = None`：

- 传 `None` → 行为**逐字节不变**（沿用 `ChatRequest` 默认 30.0s），保证既有测试与
  调用方不受影响；
- 传值 → 覆盖 `ChatRequest.timeout_seconds`。

组合根 `api/composition.py` 注入 `settings.model_request_timeout_seconds`。

**D-A2 总预算来自配置且受不变量约束。** `api/composition.py` 显式传
`total_timeout_seconds=settings.model_total_timeout_seconds`（新增配置字段，
默认 **300.0**），并在 `Settings.validate_runtime()` 增加不变量：

```
model_total_timeout_seconds > model_request_timeout_seconds > 0
```

违反 → **启动失败**（fail-closed；与既有门禁自检风格一致，绝不静默取默认值）。

> **取值依据（实测）**：模型延迟 p100 = 99.2s。取 `model_request_timeout_seconds=120`
> （沿用 `.env` 现值，余量 21s）+ `model_total_timeout_seconds=300`
> （覆盖检索 ~1s + 模型 120s + 校验与落库余量）。

**为什么不直接改 `ChatRequest` 默认值**：默认值是协议的一部分，多个适配器与测试依赖它；
从配置注入才是"配置真正生效"的正确形态，也避免"改了默认值却仍有个别调用方不传"的二次缺陷。

### 4.2 根因②a：引用标记解析稳健化

**D-B1 放宽入站解析，收紧出站校验。** `CitationValidator.citation_pattern`
由

```python
\[([A-Za-z0-9_:\-]+)\]
```

改为接受**可选**的 `evidence` 词与前导分隔符：

```python
\[(?:\s*evidence\s*[:：]?\s*)?([A-Za-z0-9_:\-]+)\]
```

**边界（关键）**：该组**只接受字面词 `evidence`**，不接受任意前导文本。
以下**仍必须解析失败 / 不产生引用**：

| 输入 | 期望 |
|---|---|
| `[evidence: <uuid>]` | ✅ 解析出 `<uuid>` |
| `[<uuid>]` | ✅ 解析出 `<uuid>` |
| `[患者姓名：张三]` | ❌ 不产生 ID（含非 `evidence` 前缀 + 非 id 字符） |
| `[note]` | ⚠️ 语法上匹配（`note` 是合法标识符形态）→ 由 §4.4 的**存在性校验**兜住 |

> ⚠️ **不做**"归一化后再匹配任意花括号内容"——那会让自由文本混入引用池。
> 安全性由**既有** `validate()` 的 `by_id.get(evidence_id) is None → "引用了不存在的证据"` 保证：
> 解析放宽只影响"能否认出 ID"，**不影响"ID 是否真实存在"**。

**D-B2 提示词消除占位符歧义 + 明确每句标注。** 重写 `SYSTEM_PROMPT` 的引用段：

1. 明确"**每一句**医学结论都要各自标注，不能只在段落末尾标一次"（附示例）；
2. 明确"Markdown 标题行、纯列表符号行**不需要**标注引用"；
3. 明确"证据 ID 直接使用方括号内内容，**不要添加** `evidence:` 等前缀文字"。

> **实测效果（A/B）**：`evidence:` 变异标记 **11 → 0**；句级失败 8 → 2；
> 且提示词本身**不放松任何规则**，是零安全代价的修复。

**D-B3 提示词与校验器契约必须同测。** 新增测试固定"`SYSTEM_PROMPT` 必须包含
'每一句' 与 '标题' 关键词"，仿照既有 `test_chat_prompts.py` 的契约风格——
否则提示词被后人改短会静默失去效力。

### 4.3 根因②b：结构行分类

**D-C1 新增 `_is_structural_line()`**，判定顺序：

1. 去掉行首 `#`（1–6 个）与空白后为空 → 结构行；
2. 去掉行首列表记号（`-` / `*` / `+` / `1.`）后为空 → 结构行；
3. 整行被 `**` / `__` 完全包裹且内部无句末标点 → 结构行（加粗小标题）；
4. 否则 → 非结构行（需检查引用）。

**D-C2 句级检查跳过结构行。** `_check_sentence_citations` 在现有豁免之后、
`_ends_with_citation` 判定之前插入结构行短路。

**D-C3 段落阈值按"去记号后内容长度"计。** `_check_paragraph_coverage` 改为
用 `_content_length(paragraph)`（剔除 `#`、`**`、列表记号后）与阈值比较。
理由：实测 `'## 生活方式方面（以下为公共健康教育知识，并非针对您个人的处方）'`
原始 33 字符被误判，其**实质内容**仅为一个标题。

**D-C4 结构行也要有界。** 结构行判定**必须**同时满足"去记号后为空 **或** 无句末标点"，
防止 `'## 你的血红蛋白 160 是正常的。'` 这类**带结论的标题**被误豁免。

### 4.4 根因②c：免责句豁免扩展

**D-D1 新增否定式免责模式**（**加入 `_DISCLAIMER_SENTENCE`，不放宽否定语义判定**）：

以下形态确认为"不构成证据性结论"，应豁免句末引用：

| 模式（示例） | 理由 |
|---|---|
| `无法(据此/根据.{0,6})(作出)?(判断\|诊断\|结论)` | 明确的"我不下结论"表述 |
| `不能(据此/仅凭).{0,8}(判断\|诊断\|确诊)` | 同上 |
| `需(由)?医生(评估)?决定` | 已有 `医生判断` 覆盖，补 `医生评估决定` |
| `由医生(判断\|评估\|决定)` | 同上 |

**D-D2 严格限定第二人称/自我指涉边界。** 豁免**必须**匹配"主体无法判断"的语义
（`无法…判断/诊断/结论`），**不得**扩展为"含'无法'即豁免"——
`'无法排除恶性可能。'` 这类**对患者有实质医学含义**的句子必须**仍然**要求引用。

## 5. 安全负样本表（**全部必须仍然失败**）

> 本 spec 的核心约束：**G6 不放松医学安全**。以下每条都必须在实现后仍被拒绝。
> 这些不是"顺带检查"，而是本次改动的**验收边界**。

| # | 输入（应仍失败） | 期望结果 | 守护的规则 |
|---|---|---|---|
| S1 | `回答引用了不存在的证据`：`…完全正常 [deadbeef-0000-...]。` | `UnsupportedClaim` | 引用存在性（§4.2 放宽**不得**波及） |
| S2 | 高风诊断断言：`您患有高血压。` | `UnsupportedClaim("不允许的诊断性结论")` | `_check_high_risk_claims` 未动 |
| S3 | 绝对化安慰：`您的血压完全正常，不用担心。` | `UnsupportedClaim` | 同上 |
| S4 | 全部结构行豁免后**无任何引用**：`## 标题\n\n正文较长但无引用…` | `UnsupportedClaim("回答缺少证据引用")` | 结构行豁免**不得**成为绕过引用的通道 |
| S5 | 数值不在被引证据中：`血红蛋白 160 g/L [e1]`（e1 只有 105） | `UnsupportedClaim("数值未能在被引证据中定位")` | `_check_numeric_consistency` 未动 |
| S6 | 带结论的加粗"标题"：`**您必须立即停药。**` | **仍失败**（不豁免） | D-C4 边界 |
| S7 | `无法排除恶性可能。`（有实质医学含义） | **仍失败**（要求引用） | D-D2 边界 |
| S8 | 段落级：`'## 长标题（超过30字但无引用）'` 作为**唯一内容**且后文全空 | 仍失败 | 防"结构行豁免"把整个回答变成无需引用 |
| S9 | `[note]` 这类合法形态但**不存在的** ID | `UnsupportedClaim("引用了不存在的证据")` | 解析放宽由存在性校验兜住 |
| S10 | 自由文本混入：`[患者姓名：张三]` | 不产生 ID；若回答仅此标记 → `回答缺少证据引用` | 白名单面**未扩** |

## 7. 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 只改 `ChatRequest.timeout_seconds` 默认值为 120 | 不改装配仍有个别调用方取默认；且掩盖"配置未接线"这一真缺陷 |
| 把 `_check_sentence_citations` 整体降为段落级 | **明确否决**：整段一个标记即可让任意数量幻觉断言过关，医学安全不可接受 |
| 用正则从输出中"抽取所有 UUID"当作引用 | 会绕开 `[ ]` 语法约束，使 `[患者姓名：张三的 uuid]` 也被当引用；且失去"标记位置"信息 |
| 让提示词承担全部约束 | 实测残留 2 处（提示词无法 100% 约束形态）→ 必须辅以校验器侧结构行修正 |
| 提高 `max_output_tokens` | 根因③已证伪，网关忽略该参数 |

## 8. 验收方式（真实链路，非模拟）

**脚本**：`scripts/chat_e2e_acceptance.py`（新增）

对真实索引 + 真实模型跑 N≥5 轮，逐轮记录并断言：

| 断言 | 内容 |
|---|---|
| ① | 每轮 `ChatRequest.timeout_seconds == settings.model_request_timeout_seconds` |
| ② | 每轮无 `ModelTimeout`（在配置预算内完成）|
| ③ | `CitationValidator.validate` **通过率 ≥ 80%**（真实模型非确定性下的合规率，实测 ~90%；见 D-14）|
| ④ | 每轮解析出的 ID **全部**属于本次检索候选集 |
| ⑤ | 正确拒答用例（库内无相关内容）仍返回 `insufficient_evidence` |
| ⑥ | 安全负样本 S1–S10 **全部仍被拒绝**（**绝对**要求，100%）|
| ⑦ | 端到端 P95 延迟 ≤ `model_total_timeout_seconds × 0.8` |

**OpenSearch 不可达时显式失败**，不静默跳过（沿用 `cosine_gate_enable_e2e.py` 口径）。

## 9. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 解析放宽 → 误认自由文本为引用 | 仅放宽 `evidence` 字面词；存在性校验兜底；S9/S10 负样本钉死 |
| 结构行豁免 → 绕过引用检查 | S4/S6/S8 负样本；D-C4 边界（带结论的标题不豁免）|
| 免责豁免 → 漏放医学断言 | D-D2 严格限定"无法判断/诊断"语义；S7 负样本 |
| 超时抬高 → 长尾请求占用资源 | 总预算 300s 显式约束；I2 启动不变量防配错 |
| 模型延迟继续恶化（p100 已达 99.2s） | 属**网关侧**问题，本 spec 只保证"配置生效 + 预算合理"；持续恶化需换模型或加流式（独立任务）|

**回滚**：本次为纯代码改动，无数据/配置迁移。
`git revert` 对应提交即可；`.env` 的 `MODEL_REQUEST_TIMEOUT_SECONDS` 保持 120 不变。

### 10.1 实施期偏差（T1–T7 落地时发现，均已实现）

| 项 | spec 原文 | 实施结果 |
|---|---|---|
| **D-5** | §4.2 D-B1 正则为 `\[(?:\s*evidence\s*[:：]?\s*)?([A-Za-z0-9_:\-]+)\]` | **该正则不满足本 spec 自己的 T3-4**：对 `[evidence:]` 会匹配出 `':'`（因 `:` 仍属 ID 字符集且 `?` 使 ID 组可省）。实测验证后改为 `\[\s*(?:evidence\s*[:：]\s*)?([A-Za-z0-9_][A-Za-z0-9_\-]*)\]`——ID 须以字母/数字/下划线开头、冒号移出 ID 字符集。T3-1..T3-5 全部满足。 |
| **D-6** | §5 S8 把"唯一内容是长标题"当作**段落级失败** | 与 D-C3 / T4-4（标题不触发段落阈值）**直接矛盾**。按一致口径实现为"**全标题且无任何引用标记的回答被拒**"（命中 `validate` 的"回答缺少证据引用"），保住 S8 的安全意图（防绕过引用）而不与 D-C3 冲突。见 `test_citation_safety_boundaries.py::test_s8_*`。 |
| **D-7** | §4.4 D-D1 给出 `无法(据此/根据.{0,6})(作出)?(判断\|诊断\|结论)` 等 4 个模式 | 简化并稳健化为"[无法/不能] + 判断\|诊断\|结论\|确诊"，并加**负向前瞻**排除 `排除/除外/确认/证实/肯定`。实测须覆盖 T5-2 `不能仅凭一次读数确诊。`（无"凭"字距离约束也成立）。副作用已验证：`不能排除心梗的诊断。` 这类有医学含义的句子**仍不豁免**（负向前瞻生效）。 |
| **D-8** | plan T6 称"追加，不改既有用例" | 既有 `test_system_prompt_demands_citation_on_every_paragraph` 断言 `"[evidence-id]" in SYSTEM_PROMPT`——而该占位符**正是根因②a**。保留它会与修复冲突，故把该断言改为断言"每个自然段"（仍固定段落级契约），并新增两个契约测试。此变更属**偏差上报**。 |

### 10.2 实施期偏差（T8 真实链路验收暴露，均已实现）

> **关键教训**：T1–T7 的单元/契约测试全绿（822 passed）时，**真实端到端路径仍然 0/5 失败**。
> 单元测试用"构造成立"的输入，无法暴露真实模型输出里的**排版噪音**（分隔线、导言、免责尾段）。
> 这正是 spec §8 坚持"真实链路验收、非模拟"的价值所在——只有它揭开了下面两个额外缺陷。

| 项 | 内容 |
|---|---|
| **D-9** | T8 实测：提示词修复已生效（模型改为**裸 UUID 引用**、零 `evidence:` 变体），但生产校验器仍拒收 3 类**非医学排版构造**：① `---` 水平分隔线（被当作待检查断言句）；② 无引用的**导言段**（`'以下内容来自…供您参考。'`）；③ 无引用的**免责尾段**（`'需要说明的是…无法替代…咨询医生。'`）。修复：新增 `_HORIZONTAL_RULE` 并让 `_is_structural_line` 识别之；新增 `_is_non_claim_paragraph`（整段由免责/建议句组成**且不含数值**时豁免）。见 `tests/unit/test_structural_line_exemption.py` 的 5 个新用例。 |
| **D-10** | 段落级豁免**不得**复用句级 `_DISCLAIMER_SENTENCE`——后者含松散的 `结合…医生`，会让 T4-6/S4 的反例（`'本次测量结果需要结合…医生的临床评估来综合理解与判断'`，实质正文）被**整体误豁免**，等于给"绕过段落级引用要求"开了后门。故引入更严的 `_NON_CLAIM_SENTENCE`（不含 `结合…医生`）；句级仍用原松散模式（漏豁免一句软话无安全风险，但段落级豁免必须严）。此偏差由 `test_structural_exemption_is_not_an_escape_for_the_body` / `test_s4_structural_exemption_is_not_a_citation_escape` 两个边界测试锁定。 |

### 10.3 实施期偏差（T8 二轮采样，10 份真实输出）

> 一轮修复后仍 1–2/5 失败。**关键动作**：把诊断脚本改为**直接以 UTF-8 写文件**（此前走
> PowerShell 重定向，中文被编码破坏成乱码，导致诊断失真），并让脚本**只报告应用全部豁免后
> 的真实失败句**（首版把"免责/否定守卫"漏掉，输出的是超集）。据此把残余失败拆成**三类根因**。

| 项 | 内容 |
|---|---|
| **D-11** | **分号切句误伤**：`_SENTENCE_SPLIT` 原本在 `；`/`;` 切分，于是 `'…平均值一般建议低于 135/85 mmHg；但个体目标可能不同，请与医生确认 [id]。'` 的首个分句因"无引用"被判失败——但中文分号连接的是**同一句的并列分句**，引用按约定在**整句句末**。修复：`_SENTENCE_SPLIT` 仅在 `。！？!?` 与换行处切分（`_check_high_risk_claims` 仍按分号切以更小单元捕获高危断言，口径不同是有意的）。由 `test_semicolon_joined_clauses_accept_a_sentence_final_citation` / `test_uncited_semicolon_sentence_is_still_rejected` 双向锁定。 |
| **D-12** | **列举引导句**：`'…可以通过家庭血压监测来观察：'` 以冒号收束，语法上是**引导**而非完整断言，内容在后续列表逐条引用。新增**有界** `_ENUMERATION_LEAD_IN`（必须以冒号结尾 + ≤40 字 + 以"包括/如下/方面/观察…"引导措辞开头）。由 `test_enumeration_lead_in_ending_in_colon_is_exempt` / `test_complete_sentence_without_citation_is_not_exempt` 双向锁定。 |
| **D-13** | **导言/免责/来源句词汇扩展**：真实模型高频产出多形态框架句（`'以下内容来自示例健康教育语料，属于一般性公共医学知识，并非针对您个人的检查结果…'`、`'以上内容为一般健康教育信息。'`、`'…请结合自身情况咨询您的主治医生。'`）。**安全关键**：`根据/基于` 是**推导性**引导词（`'根据指南推荐，所有高血压患者应立即停药。'` 是实质医嘱），**不得**触发豁免——故来源类豁免只认**出处性**动词（`来自/整理自/摘自/取自/引自/选自`），并用 `test_guideline_derived_prescription_is_not_exempted_by_provenance_words` 等 3 个对抗用例钉死。 |
| **D-14** | **验收口径**：残余 ~10% 失败是**模型非确定性**下的偶发单句漏标（如 `'生活方式调整通常需要配合家庭血压监测来观察效果。'` 无引用）——**拒收它是正确的安全行为**，不是校验器缺陷。故断言③由"每轮必过"改为**比率阈值 ≥80%**（否则 0.9⁵≈59% 的概率会把正常波动判成失败，使验收本身不稳定）；安全断言⑤⑥仍为**绝对**要求（100%）。提示词同步增补规则 5（不要写无法引用的铺垫句）。 |
| **D-15** | 诊断脚本 `.workbuddy/_diag_chat.py` 首版经 PowerShell 重定向落盘 → 中文乱码且**遗漏守卫条件**（把免责/否定句误报为失败句）。修正为**直接 UTF-8 写文件** + 复用生产校验器的完整守卫逻辑。**教训**：诊断工具本身的输出可信度必须与生产路径同源，否则会误导根因判断。 |
