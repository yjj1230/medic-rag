# Medical RAG 安全、交付与质量加固设计

## 目标

将当前医疗 RAG 项目从“代码级可演示”推进到“可重复构建、可审计、可进行真实质量验收”的状态。工作按安全收敛、交付恢复、部署一致性、上传安全与审计、医疗质量复评五个阶段顺序执行；每个阶段都有独立的验证证据。

## 当前基线

- 后端源码已存在，Python 文件可通过 `py_compile`，但运行时依赖和完整测试环境尚未恢复。
- 检索服务已有混合 RRF、引用校验、访问控制和余弦门禁实现；门禁是否进入容器由 Compose 配置决定，不能只看源码。
- `frontend/src` 缺失，现有前端 Dockerfile 的源码构建链不完整。
- `.env`、数据库和备份文件位于共享目录，必须按真实凭据和 PHI 暴露处理。
- 上传服务默认使用 `AllowAllVirusScanner`，上传动作没有完整审计事件。
- 历史评测显示混合检索质量较好，但拒答率和忠实度仍不足以支持临床生产用途。

## 设计原则

1. 安全问题先收敛，再进行功能恢复；旧密钥在外部服务确认撤销前不得继续使用。
2. 不从 `dist/` 或历史报告臆造缺失的前端业务源码；优先从 Git、备份和构建产物中的 source map 恢复，无法恢复时明确标记为阻塞。
3. Compose、`.env.example`、Dockerfile 和 Settings 必须表达同一套配置契约；关键配置缺失或不一致时启动失败。
4. 医疗文件上传默认 fail-closed：没有病毒扫描器时生产启动或上传请求必须被拒绝。
5. 每个质量结论都必须对应新鲜命令输出或真实链路产物；历史报告只能作为线索，不能作为当前通过依据。

## 阶段设计

### 阶段一：凭据与 PHI 收敛

轮换模型网关 API key、OCR 密码以及对象存储、数据库、Redis、JWT 等运行凭据；将新值注入本地密钥来源，不把真实值写回 Git。共享目录中的数据库、数据库备份、私有索引备份和 PHI 缓存先移动到受控隔离目录，完成哈希清单后再删除共享副本。远程模型和 OCR 端点必须使用 HTTPS 或回环地址；开发环境也不能用真实 PHI 访问公网明文端点。

验收：旧密钥在服务侧已撤销；`rg` 不再从项目目录命中真实凭据；共享目录无数据库/备份/PHI 缓存；配置检查能拒绝远程明文 PHI 出口。

### 阶段二：前端与测试交付恢复

按顺序检查 Git 对象、恢复副本、构建产物 source map 和外部备份，恢复 `frontend/src` 以及原有测试目录。恢复后保持现有 API 契约，补齐前端构建入口和测试脚本。无法恢复的内容不得用空壳替代；交付报告列出缺失文件及其影响。

验收：`frontend` 可执行 `npm ci && npm run build`；后端依赖可安装；测试目录恢复到与 Git 清单一致；测试和构建命令的失败数有明确记录。

### 阶段三：Compose 与运行时配置一致性

统一 Compose 环境注入方式，显式传递 `CALIBRATION_ARTIFACT_PATH`、向量模型路径、分析器、超时和模型配置；将 `config/` 和必要的本地模型通过镜像复制或只读卷挂载提供给服务。API 端口默认绑定回环，外部暴露由部署层显式配置。`Settings` 对未知安全配置采用拒绝或告警策略，避免键名静默失效。启动自检必须证明标定产物已加载并实际启用余弦门禁。

验收：使用示例配置可生成完整 `docker compose config`；容器内路径均可读；`/health/ready` 可区分依赖不可用、索引降级和门禁未启用；启动日志包含门禁阈值、分数空间和索引版本。

### 阶段四：上传安全与审计

增加生产病毒扫描器适配器和配置校验；生产环境禁止 `AllowAllVirusScanner`。增加 `DOCUMENT_UPLOADED` 审计动作，在文件校验、扫描、对象存储写入和数据库事务成功后记录租户、患者、文档和版本标识，不记录原文。为审计查询补充资源维度索引，并为迁移、失败回滚和重复上传写回归测试。

验收：未配置扫描器的生产上传被拒绝；扫描失败不会留下可检索文档；上传成功有审计事件；删除和上传事件可以按患者、文档和时间查询。

### 阶段五：医疗质量复评

先安装依赖并运行静态检查、单元测试、迁移测试和离线门禁测试；再启动 OpenSearch、数据库、Redis、对象存储和模型网关，复跑真实检索矩阵。评测分为检索质量、拒答准确率、引用正确性、数值忠实度、权限隔离和删除残留六组。忠实度结果必须区分规则判定、模型判定和人工临床复核，任何数值矛盾都阻断生产结论。

验收：报告记录数据集哈希、索引版本、模型版本、配置快照、样本数、置信区间和失败案例；拒答集不再以 0% 作为通过；关键医学声明经过临床人员抽样复核。

## 不在本次范围内

- 不把系统升级为诊断、处方或治疗决策系统。
- 不通过人工编写空壳前端来掩盖缺失的原始业务源码。
- 不把历史评测数字直接改写成当前通过结论。
