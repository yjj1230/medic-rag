# 医疗患者端企业级 RAG 设计

## 1. 文档信息

- 日期：2026-09-09
- 状态：设计已在对话中确认，待用户审阅
- 目标：建设面向患者端的医疗知识问答与报告解释 RAG MVP
- 部署：专有云 / VPC
- 规模：试点用户不超过 1,000，月处理报告不超过 10,000 份，并发不超过 20

## 2. 背景与目标

系统面向患者提供健康教育、医学术语解释、检查项目说明和患者报告解释。系统允许患者上传 PDF、图片、Word 和 Excel 报告，支持中文和英文。

系统使用外部企业级模型服务，但患者身份、授权、权限、原始文件、结构化指标、检索和审计由本系统控制。RAG 负责为 LLM 提供经过权限过滤、可定位的医学证据，避免模型仅凭训练记忆回答。

## 3. 范围

### 3.1 MVP 包含

- 实名登录与患者身份绑定
- 上传 PDF、图片、Word、Excel
- 中英文文本与 OCR 解析
- 表格、页码、坐标和来源锚点保留
- 患者报告中的医学指标结构化抽取
- 公共医学知识问答
- 患者报告解释
- 混合检索、重排序和引用
- 急症与高风险问题安全分流
- 外部模型调用网关
- 审计、监控、删除和失败重试

### 3.2 明确不包含

- 自动诊断
- 自动开处方
- 自动调整药物或剂量
- 确定性治疗方案
- 替代医生进行临床决策
- 第一版全自动 Agent
- 将患者数据写入公共知识库

## 4. 已确认的架构决策

1. 采用模块化单体加独立异步任务服务。
2. 部署在专有云 / VPC 中。
3. 允许原始报告发送到外部模型，但仅使用企业级 API。
4. 外部模型供应商必须承诺不训练、不复用患者数据，并明确数据留存和区域。
5. 患者必须实名登录，并在上传或外发前完成明确知情同意。
6. 首批知识来源采用官方资料、专业学会指南和医学专家审核内容。
7. 首版支持中英文以及 PDF、图片、Word、Excel。
8. 患者资料与公共医学知识分开存储、索引和授权。

## 5. 总体架构

```text
患者端 Web / App
        |
API 网关与认证
        |
患者 RAG 核心服务
  |- 会话与问答
  |- 患者授权
  |- 查询分类与安全分流
  |- 检索编排
  |- 引用生成
  `- 审计记录
        |
权限过滤后的检索层
  |- 公共医学知识库
  `- 患者私有资料库
        |
回答生成与安全校验
        |
答案、引用和风险提示

文件上传 -> 对象存储 -> 异步解析任务服务 -> 患者私有资料库
                         |- 病毒扫描
                         |- PDF / 图片 / Word / Excel 解析
                         |- 中英文 OCR
                         |- 表格识别
                         |- 医学指标抽取
                         `- 索引构建
```

患者端不能直接访问模型服务、数据库或对象存储。外部模型只能通过模型出口网关访问。模型不能直接查询数据库、修改患者数据或调用未授权工具。

## 6. 核心模块

### 6.1 患者端与认证模块

- 实名账号、患者身份和租户绑定。
- 保存知情同意协议版本、时间、用途和撤回状态。
- 每次问答和文件访问都校验患者、租户、资源归属和授权状态。

### 6.2 文件接收与解析模块

- 校验文件类型、大小、格式和病毒。
- 原始文件写入对象存储，解析过程通过持久化任务表和可靠队列异步执行。
- 解析结果保留语言、页码、坐标、OCR 置信度、表格结构和文件版本。
- 低置信度结果标记为待确认，不直接作为确定事实。

### 6.3 医学事实抽取模块

对报告抽取指标、单位、参考范围、采样时间、报告时间、异常标记和来源锚点。抽取结果必须保留原文证据，不能只保存模型改写后的文本。

### 6.4 知识治理模块

公共资料白名单至少记录：来源机构、标题、版本、发布日期、适用范围、语言、审核人、审核时间和失效状态。知识内容经过切分后形成可引用的证据单元。

### 6.5 检索编排模块

- 根据问题识别普通知识、报告解释、用药相关和高风险 / 急症类别。
- 公共医学知识与患者私有资料分别检索。
- 使用关键词与向量混合检索，再进行重排序。
- 权限过滤必须在重排序和上下文组装之前完成。
- 证据不足时进入拒答或降级路径。

### 6.6 模型出口网关

统一封装对话 LLM、Embedding、Reranker、OCR / 多模态模型和安全分类模型。网关负责供应商白名单、授权检查、数据外发策略、超时、重试、限流、成本和调用审计。

能用结构化指标回答时，不发送完整原始文件。只有需要版面或视觉理解时，才将原始 PDF 或图片发送给支持视觉输入的企业级模型。

## 7. 数据分层与存储

### 7.1 原始层

保存患者上传的原始 PDF、图片、Word 和 Excel。原始文件放在对象存储中，具备版本、加密、访问控制和删除状态。

### 7.2 解析层

保存 OCR 文本、原生文本、表格、页面、坐标、语言、解析置信度和解析版本。

### 7.3 医学事实层

示例字段：

```text
指标名称、结果值、单位、参考范围、采样时间、来源页码、原文坐标、置信度、患者 ID、租户 ID
```

### 7.4 检索层

公共知识索引和患者私有索引分开管理。患者索引必须带患者 ID、租户 ID、文件 ID、授权范围和删除状态等过滤字段。

建议组件：

- PostgreSQL：用户、租户、授权、版本、结构化指标、任务状态和审计索引
- OpenSearch / Elasticsearch：全文、向量、过滤和重排序候选集
- S3、MinIO 或企业对象存储：原始文件和解析产物

删除操作必须传播到原始文件、解析文本、结构化指标、向量、缓存、摘要和其他派生数据。

## 8. 查询与回答流程

```text
患者问题
  -> 问题分类与急症识别
  -> 权限校验
  -> 公共知识与患者资料分别检索
  -> 混合检索与重排序
  -> 证据完整性检查
  -> 受控 LLM 生成
  -> 引用校验与安全校验
  -> 返回答案、来源和风险提示
```

患者报告只用于说明患者材料中记录的事实。医学解释优先来自权威公共知识。回答必须区分报告事实、一般医学含义和下一步建议。

推荐交付结构：

1. 简要结论或解释
2. 报告中的相关事实
3. 一般医学含义
4. 需要注意的风险
5. 建议下一步
6. 证据来源
7. 医疗安全提示

## 9. LLM 使用约束

LLM 只能基于传入证据生成回答。提示与输出校验必须要求：

- 没有证据时明确说明不确定或无法可靠回答。
- 不把患者报告中的单项异常直接解释为诊断。
- 不自动开药、停药、改药或给出确定性治疗方案。
- 关键医学结论附带可定位来源。
- 识别急症信号时优先输出就医提示。

第一版不允许全自动 Agent 自主访问患者数据或执行外部操作。

## 10. 安全、隐私与合规

- 使用专有云 / VPC，外部模型仅允许经出口网关访问。
- 网络采用域名白名单、最小权限、加密传输和出站审计。
- 患者数据、租户数据和公共知识采用隔离的权限边界。
- 外部模型供应商必须提供不训练、不复用、留存周期和数据区域承诺。
- 每次外发记录患者、授权版本、文件或片段、模型、时间、目的和结果。
- 撤回同意后停止外发；删除请求必须触发全链路删除任务。
- 模型服务不可用时返回可解释的降级提示，不进行无控制重试。

## 11. 风险分流

### 普通解释

返回医学科普、指标说明和报告事实，附来源和限制说明。

### 高风险问题

对“是否癌症”“能否停药”“是否需要调整剂量”等问题，不返回确定性诊断或用药指令，转为风险说明和医生咨询建议。

### 急症信号

对严重胸痛、呼吸困难、意识异常、大量出血等信号，优先显示及时就医或急诊提示，不等待复杂检索和长篇生成。

## 12. 可观测性与审计

使用结构化日志和 OpenTelemetry 跟踪：

- 请求 ID、患者 / 租户标识、授权版本
- 检索来源、证据 ID、模型和版本
- 外部调用延迟、状态和成本
- OCR / 抽取置信度
- 安全拦截和人工复核结果
- 文件解析、删除和重试状态

日志不得泄露不必要的患者原文，应支持按患者、文件、请求和模型调用追溯。

## 13. 评估与验收

评估集覆盖普通问答、报告解释、双语、多格式、表格识别、事实冲突、急症、用药、诊断请求、越权和删除残留。

首版目标：

- 患者资料越权率：0
- 删除后残留召回：0
- 关键医学结论引用完整率：不低于 95%
- 引用与原文一致率：不低于 95%
- 高风险越界回答：0
- 普通问答 P95 延迟：8 秒以内
- 解析失败可追踪、可重试、可人工处理

上线前必须完成医学人工审核、权限测试、删除链路测试、模型红队测试和外部服务故障演练。

## 14. 分阶段交付

### Phase 0：知识和安全基础

完成资料白名单、版本管理、授权、删除、审计和评估集。

### Phase 1：公共医学知识问答

完成术语解释、检查说明、一般指标含义、风险分流、混合检索和引用。

### Phase 2：患者报告解释

完成多格式解析、OCR、表格识别、医学指标抽取、患者私有索引和报告引用。

### Phase 3：运营闭环

完成监控、人工复核、供应商质量评估、成本控制和故障演练。

后续再评估医生端、时间线、文献辅助和受控 Agent。

## 15. 需要在实施前明确的供应商配置

以下内容属于实施配置，不改变总体架构：

- 外部 LLM、Embedding、Reranker 和 OCR 供应商
- 模型 API 的数据留存和区域条款
- 对象存储和 OpenSearch 的具体产品
- 实名认证、短信或身份服务
- 医学内容审核责任人和审核周期
