## 四、复跑命令与验收标准

```powershell
# 1) 确认 OpenSearch 就绪
Invoke-RestMethod http://127.0.0.1:9200

# 2) 快速门禁对比（4 配置，含 1 个门禁档）
python scripts/retrieval_tuning_lab.py --quick --rounds 5 --out eval_out/gate_rerun

# 3) 完整矩阵（7 配置，含 2 个门禁档）
python scripts/retrieval_tuning_lab.py --rounds 25 --out eval_out/gate_rerun_full
```

**验收标准**

1. `G1/G2` 门禁档的 `rejection.accuracy` 应显著高于 `A3/D2` 无门禁档（历史基线恒为 **0.00**）。
2. 门禁档的 `quality.recall_at_k` / `mrr` 相对 `A3` 的**下降幅度**即门禁误杀的代价，需一并报告（这是门禁调参的真实 trade-off）。
3. `safety.all_zero` 必须为 `true`（零容忍）。
4. `meta.corpus_integrity` 的 `public/private` 计数应非 0；若为 0 或 `unavailable`，说明语料未加载，不得当作检索退化。

**产出物**：`eval_out/gate_rerun/retrieval_eval_results.json` —— 即「拒答准确率 0% → X%」这条简历/面试数字的直接证据。

## 五、口径差异（务必注意）

1. **gold 口径**：重建版按规范 `gold_evidence_ids` 计指标；历史 grouped 口径额外使用 `gold_evidence_groups` 的等价组语义（故历史 `accepted_hit_rate=1.0000` 略高于按规范 gold 的值）。门禁对比（拒答准确率）不受该差异影响；若要复现 grouped 数字，需另接分组口径。
2. **身份映射**为取证推断，首次真实复跑后请与 `eval_out/test_v2_1_run` 的逐例 `returned_ids` 抽样比对，确认 public/private/safety 三类身份无误。
3. **延迟口径**：本版按每条用例采样一次、`--rounds` 控制重复轮数；历史 `latency.rounds` 语义未完全对齐，横向比较 C95 时以同一版 runner 内对比为准。
4. **未重建的脚本**：`scripts/retrieval_rejection_threshold_sweep.py`（阈值扫描）、`scripts/faithfulness_eval.py`（忠实度）等仍未重建，属后续任务。
