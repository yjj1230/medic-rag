## ⚠️ 2026-09-24 更正与落地记录（先读）

**更正一：本报告把 `vector_score` 称为"向量余弦相似度"，这个标签是错的。**

实测（三例吻合，误差 <1e-3）：索引 mapping 建立时**未声明 `space_type`**，OpenSearch
对 `knn_vector` 的默认值是 `l2`，因此检索返回的分数是 **`s = 1/(1+L2²)`**，不是真余弦。
对已 L2 归一化的向量：`s = 1/(3−2·cos)`，即 `cos = 1.5 − 0.5/s`。

**这是余弦的严格单调变换**，所以"按该分数排序 == 按余弦排序"成立，
**本报告的全部排序结论与门禁有效性结论不受影响**；但数值语义不同：

| 真余弦 | `1/(1+L2²)` | 含义 |
|---|---|---|
| 0.4556 | 0.4788 | 不相关最大值 |
| 0.4951 | 0.4976 | 分离中点 |
| **0.5000** | **0.5000** | **巧合：两空间仅在 0.5 处数值相同** |
| 0.5346 | 0.5179 | 相关最小值 |

因此**阈值必须连同"分数空间"一起声明**（生产实现已通过
`CalibrationArtifact.score_space` 消歧，本次取 `"l2_inv"`）。**不要把 0.5 处的数值巧合
推广到其他阈值**（余弦 0.53 → `l2_inv` 0.5155，不相等）。

**更正二：§4 推荐的"门禁作用范围"选了 `intersect`，理由需补充。** `intersect` 在大语料下
有一个未被测到的风险：词法候选若不在向量 top-`candidate_limit` 内（`vector_score=0`）会被
一并剔除。当前语料 12 条测不出该风险；语料扩充后需重测 `intersect` vs `emptiness`。

**落地状态（2026-09-24）**：余弦门禁已进入生产代码，真实链路验收 4/4 通过

## 0. 执行摘要（先看这一段）

本次评估最重要的产出不是"参数调到多少"，而是发现了一个**上线级别的缺陷**：

> **当前生产配置永远不会拒答。** 与知识库毫无关系的问题（如"乳腺癌的靶向治疗方案"、"我的胸部 CT 结果"）都会返回满额 top_k 条高血压/血常规内容，`reason` 为 `None`，链路状态为 `ok`。

根因是两件事叠加：

1. `RetrievalService` 默认走 `GatePolicy.TOP_K`——**没有任何相关性门禁**，入选范围完全由 `top_k` 决定（这是项目此前有意修正"0.5 魔数门禁砍空结果"的副作用）。
2. 唯一可用的分数 `calibrated_score`（RRF 归一化）**不具备相关性判别力**。它衡量的是"两路检索是否一致地把该文档排在前面"，而不是"该文档是否相关"。候选池只有 5~7 条时，两路都必须返回 top-N，于是每篇文档都同时出现在两个榜单里，分数被压缩进 `[0.9385, 1.0]`——相关与不相关内容**几乎完全重叠**。

修复方向已验证：**改用向量余弦相似度的绝对阈值门禁**。余弦保留了绝对尺度，存在干净的分离间隔（不相关 ≤0.4556，相关 ≥0.5346）。在阈值 0.50 上实测：

| 指标 | 生产现状（无门禁） | 余弦门禁 0.50 |
|---|---|---|
| 拒答正确率 | **0/2** | **2/2** |
| 拒答用例平均返回条数 | 3.00 | 0.00 |
| 可答用例命中率 | 1.000 | 1.000（**零损失**） |
| MRR / nDCG@k | 0.964 / 0.946 | 0.964 / 0.946（**零损失**） |
| 零容忍安全违规 | 0 | 0 |

对医疗 RAG 而言，这是比排序质量更严重的问题：LLM 拿到 3 条不相关的高血压内容，仍可能组织出一段看似有据的回答；而正确的行为是明确回答"证据不足"。

## 1. 评估部分

### 1.1 核心指标定义

检索链路按四个维度度量，**安全维度优先级最高**：

#### （1）排序与召回质量（需标注真值）

| 指标 | 公式 | 说明 |
|---|---|---|
| **命中率** Hit@K | `1[∃ top_i ∈ gold]` | 至少召回一条相关证据；衡量"有没有找到" |
| **召回率** Recall@K | `\|top_K ∩ gold\| / min(K, \|gold\|)` | 分母用 `min(K,\|gold\|)`，使"找齐可及相关项即满分" |
| **查准率** Precision@K | `\|top_K ∩ gold\| / K` | 衡量上下文里有多少是噪声 |
| **MRR** | `mean(1 / rank_first_gold)` | 首条相关证据的位置；衡量排序质量 |
| **nDCG@K** | `DCG / IDCG`，二元相关性，重复 id 只计一次 | 整体排序质量，防"靠重复刷分" |

**采集口径红线（项目既有约定，本次严格遵守）**：
- 必须**真实调用** `RetrievalService.retrieve`。`eval/golden.py:_rag_metrics_for_fixture` 的"模拟检索"让 recall/MRR **数学必然为 1.0**，不能作为验收依据。
- 必须**显式传 `k=top_k`**。`evaluate_retrieval` 的 `k` 默认取传入列表长度，不传会让"把全部候选都返回"的配置获得虚高召回。
- 本次采用**双口径**统计：`raw`（按索引 ID）与 `dedup`（按 `content_hash` 归组）。私有库 7 条记录中 4 条文本完全相同，按索引 ID 计算召回会虚高——**排序指标一律用去重口径解读**。

#### （2）零容忍安全项（非零即无条件失败）

| 指标 | 含义 | 本次是否真实覆盖 |
|---|---|---|
| `permission_violations` | Top-K 中出现不可访问证据的次数 | ✅ 真实覆盖（跨患者 / 跨租户身份触发） |
| `deletion_residuals` | Top-K 中出现已删除证据的次数 | ⚠️ **未覆盖**（语料中无 `deleted=true` 记录） |
| `review_required_leakage` | Top-K 中出现 `retrieval_eligible=false` 的次数 | ⚠️ **未覆盖**（语料中无该状态记录） |

未覆盖的两项**明确标注为未覆盖**，而不是编造一条记录凑指标。它们当前只能证明"过滤逻辑未误伤正常数据"，不能证明"残留会被拦住"。

#### （3）拒答正确性（本次新增，原评估方案缺失）

| 指标 | 定义 |
|---|---|
| **拒答正确率** | 知识库确实无相关内容时，返回条数为 0（`reason=insufficient_evidence`）的比例 |
| **拒答用例平均返回条数** | 应拒答却返回内容的严重程度 |

**为什么必须补这一项**：原评估方案的 D2 只度量"给定 gold 时排得好不好"，**默认了"总能找到东西"**。但医疗场景里"该拒答而没拒答"（把不相关内容当证据）与"该回答而拒答"（漏答）是两类不同且都严重的错误，必须分开度量。

#### （4）延迟

| 指标 | 采集点 |
|---|---|
| 端到端 P50/P95/P99 | `diagnostics.stage_elapsed_ms["total"]` |
| 分阶段 P95 | `lexical` / `vector` / `fusion` / `rerank` |
| 降级率 | `diagnostics.embedding_degraded` / `lexical_error` / `vector_error` |

补充指标：**上下文冗余度** `1 − 唯一内容数 / 返回条数`，衡量 Top-K 槽位被重复内容浪费的比例（D2-3）。

### 1.2 量化评估方法

```
① 语料勘察      直连 OpenSearch 拉取全部记录（id / content_hash / 可见性 / 文本）
                → 人工判定语义归属，识别重复与乱码记录
      │
② 评估集构建    18 条用例，分三类：
                · quality   14 条  —— 可答，标注真实 gold 证据 ID
                · rejection  2 条  —— 知识库确实无此内容，期望返回空
                · safety     2 条  —— 跨患者 / 跨租户，期望返回空且零违规
      │
③ 逐配置检索    每个用例真实调用 RetrievalService.retrieve（显式 k=top_k）
      │
④ 指标计算      evaluate_retrieval（raw）+ 去重口径（dedup）+ 冗余度
      │
⑤ 延迟采样      每配置对 4 条代表查询重复 25 轮，取分位
      │
⑥ 安全扫描      索引可见性错配计数（公共索引不得含 private 记录，反之亦然）
```

## 2. 调参部分

### 2.1 影响检索效果的关键参数

| 参数 | 代码位置 | 当前值 | 作用 |

| `query_prefix` | `LocalFastEmbedModel` | 无 | bge 查询指令前缀 |
| 向量缓存 | `CachedEmbeddingModel` | 启用 | 重复文本免重算 |

### 2.2 对比实验方案

| 组 | 目的 | 配置 |
|---|---|---|
| A | 检索模式 | 纯词法 / 纯向量 / 混合 |
| B | RRF k 敏感性 | k = 10 / 30 / 60 / 100 |
| C | top_k 敏感性 | k = 1 / 3 / 5 |
| D | candidate_limit 敏感性 | 5 / 10 / 20 / 50 / 100 |

| vector | 30.4 ms | kNN 向量候选 |
| fusion | 0.2 ms | RRF 融合 |
| rerank | 0.0 ms | 未装配重排模型 |
| **total** | **131.1 ms** | 端到端 |

词法/向量两路**并行执行**，端到端 ≈ `max(lexical, vector) + fusion`，而非两者之和。当前 P95 131ms 优于方案设定的 800ms 目标。

### 2.5 参数敏感性结论

| 参数 | 敏感性 | 结论 |
|---|---|---|
| **检索模式** | **高** | 混合 MRR 0.964 > 向量 0.929 > 词法 0.893。混合相对词法 **+0.071**，相对向量 **+0.036**，且上下文冗余最低（0.167）。**必须保持混合。** |
| **RRF k** | **无** | k=10/30/60/100 的 MRR 全部为 0.964，**极差 0.000**。最优候选在两路中排名都靠前时，`1/(k+rank)` 的相对关系不随 k 变化。**保持 60，无需调参。** |
| **top_k** | **高** | k=1 → 召回 0.929 / 查准 0.929 / 冗余 0；k=5 → 召回 1.000 / 查准 0.214 / 冗余 0.214。**召回与查准/信息密度直接对冲。** |
| **candidate_limit** | **测不出** | 5~100 结果完全一致。候选池（public 5 + private 7）本身小于任何被测上限，**截断从未生效**。当前测得的"最优值"没有意义，**必须等语料规模上来后重新标定**。 |
| **rerank_limit** | **未测** | 未配置 `rerank_model`，重排阶段空转（P95 = 0.0ms）。装配重排模型后需重测。 |
| **门禁策略** | **极高** | 见 §3。rank_gate=1 直接把召回压到 0.893；而完全无门禁则永不拒答。**这是本报告最关键的参数。** |
| **查询指令前缀** | **负收益** | 纯向量 MRR 0.929 → 0.857，混合 0.964 → 0.893，且延迟上升约 15ms。该前缀面向"短查询检索长文章"（s2p），而本项目 query 已是完整问句、文档块仅百余字，**场景不匹配**。**不要启用。** |
| **向量缓存** | **单次无收益** | 单次检索每个 query 只编码一次，缓存命中率恒为 0。P50 从 89ms 降到 50ms 属测量波动。**价值在多用户重复提问场景，保留即可。** |

## 3. 核心发现：门禁失效与修复

### 3.1 缺陷取证

拒答用例的实测返回（`scripts/retrieval_rejection_probe.py`）：

```
[pub-out-of-scope] 乳腺癌的靶向治疗方案有哪些？
  gate_policy=top_k  gate_passed=5  reason=None          ← 无门禁
    7ebdec91… cal=0.9919  lex_rank=2  vec_rank=1         ← 高血压用药内容
    7498fde6… cal=0.9841  lex_rank=1  vec_rank=3         ← 家庭血压测量内容
    4b7574b9… cal=0.4919  lex_rank=None vec_rank=2

[priv-out-of-scope] 我的胸部 CT 结果是什么？
  gate_policy=top_k  gate_passed=12  reason=None         ← 无门禁
    2a555496… cal=1.0000  lex_rank=1  vec_rank=1         ← 血常规报告
    217aec3f… cal=0.9839  lex_rank=2  vec_rank=2
    0685db7f… cal=0.9683  lex_rank=3  vec_rank=3
```

完全不相关的查询返回了**分数接近满分**的结果。原因：

1. `gate_policy=top_k` → 无相关性过滤，`top_k` 决定一切。
2. `calibrated_score` 的取值被压缩进极窄区间——**与查询无关**。

### 3.2 为什么 RRF 归一化分数无法判别相关性

分数分布实测：

| | 相关（gold 命中） | 不相关（噪声） |
|---|---|---|
| RRF `calibrated_score` | 0.9385 ~ 1.0（p50 0.9839） | 0.9385 ~ 0.9919（p50 0.9683） |

**两者几乎完全重叠。** RRF 的设计目标是"融合两路排名"，其归一化上界 `2/(k+1)` 对应"两路都排第一"。候选池只有 5~7 条时，两路各自必须返回 top-N，于是**每篇文档都会同时出现在两个榜单里**，分数被压缩到 `[0.93, 1.0]`。

用该分数做阈值门禁的实测效果（阈值扫描）：

| 阈值 | 拒答正确 | 可答命中率 |
|---|---|---|
| 0.469 ~ 0.976 | 0/2 | 1.000 |
| 0.984 | 0/2 | 0.929 |
| 0.992 | **1/2** | 0.714 |

**最好也只能做到拒答 1/2，且可答命中率掉到 0.714。** 结论：**在 RRF 归一化分数上做门禁是方向性错误**，不是调参问题。

### 3.3 修复：向量余弦绝对阈值门禁

原始分数保留了绝对尺度（`scripts/retrieval_raw_score_probe.py`）：

| 分数 | 相关 | 不相关 | 是否可分 |
|---|---|---|---|
| **BM25** | 1.439 ~ 15.10 | 0.312 ~ 4.778 | ❌ 区间重叠严重 |
| **向量分数**（`1/(1+L2²)`，非真余弦，见文首更正） | **0.5346 ~ 0.6724** | **0.4073 ~ 0.4556** | ✅ **干净分离** |

余弦的分离间隔：不相关最大值 0.4556 < 相关最小值 0.5346，**中点 0.4951**。

端到端验证（`scripts/retrieval_gate_prototype.py`）：

| 阈值 | 命中率 | 召回 | 查准 | MRR | nDCG | 拒答正确 | 零容忍 |
|---|---|---|---|---|---|---|---|
| 无门禁（现状） | 1.000 | 0.964 | 0.333 | 0.964 | 0.946 | **0/2** | 0 |
| 0.45 | 1.000 | 0.964 | 0.333 | 0.964 | 0.946 | 1/2 | 0 |
| **0.48** | 1.000 | 0.964 | 0.333 | 0.964 | 0.946 | **2/2** | 0 |
| **0.50** | 1.000 | 0.964 | 0.333 | 0.964 | 0.946 | **2/2** | 0 |
| **0.53** | 1.000 | 0.964 | **0.512↑** | 0.964 | 0.946 | **2/2** | 0 |
| 0.56 | 0.786 | 0.750 | 0.512 | 0.750 | 0.732 | 2/2 | 0 |
| 0.60 | 0.571 | 0.536 | 0.429 | 0.571 | 0.544 | 2/2 | 0 |

**阈值 ∈ [0.48, 0.53] 时，拒答 2/2 且排序指标零损失；0.53 处查准率还从 0.333 提升到 0.512。**

门禁作用范围有两种实现，实测在阈值 ≤0.53 时等价：

- `intersect`：词法候选也须通过余弦门禁（更严格，高阈值下查准更优）
- `emptiness`：仅要求"存在通过门禁的向量候选"，词法候选全保留（更保守，大语料下能保住 BM25 的精确术语匹配）

**推荐 `intersect`**：语义更清晰（门禁即"相关性准入"），且实测高阈值下查准率更好。

### 3.4 修复的边界与前提

1. **阈值必须标定，不得硬编码。** 0.50 是**当前 embedding 模型（bge-small-zh-v1.5）+ 当前语料**下的标定值。更换向量模型、切到网关后端（1536 维）、或语料分布变化后必须重新标定——这与项目既有的 `CalibrationArtifact` 机制（绑定 `embedding_model` + `index_version` + `eval_dataset_version`）设计意图一致。
2. **样本量小。** 分离间隔来自 30 条相关 + 62 条不相关候选，评估集仅 18 条用例。0.50 应视为**冷启动初值**，需在真实评测集上复核。
3. **拒答是"检索层拒绝"，不等于"回答层拒绝"。** 门禁让 `reason=insufficient_evidence` 且 `items=[]`，编排器（`chat/orchestrator.py`）据此返回"当前没有足够且可定位的医学证据"并跳过 LLM 调用。链路是通的，但**回答层的引用校验不构成第二道防线**——现状下不相关内容会带 citation 一起进入 prompt，因此检索层门禁是必需的。

## 4. 推荐最优配置

```python
RetrievalService(
    index,                                    # OpenSearchStore（混合候选接缝）
    embedding_model=...,                      # 本地 bge-small-zh-v1.5，512d
    embedding_model_name="BAAI/bge-small-zh-v1.5",
    embedding_dimensions=512,
    ranker=HybridRanker(rrf_k=60),            # 敏感性为 0，保持默认
    candidate_limit=50,                       # ⚠️ 待大语料重新标定
    rerank_limit=None,                        # ⚠️ 装配重排模型后重新标定
    # ↓↓↓ 本次唯一需要改动的生产参数 ↓↓↓
    # 用向量余弦绝对阈值门禁替代"无门禁"：
    #   gate_policy = cosine_absolute, threshold = 0.50
)
```

| 参数 | 推荐值 | 依据 |
|---|---|---|
| 检索模式 | **hybrid** | MRR 0.964 最优，冗余最低 |
| `rrf_k` | **60**（不变） | 敏感性为 0，极差 0.000 |
| `candidate_limit` | **50**（不变，待重标定） | 当前语料测不出差异 |
| `top_k` | **3** | 医疗问答宁精勿多；k=1 会掉召回（0.929），k=5 冗余翻倍 |
| **门禁** | **余弦绝对阈值 0.50** | 唯一能同时保证拒答正确与零损失的方案 |
| 查询前缀 | **不启用** | 实测负收益（MRR −0.071） |
| 向量缓存 | **保留** | 多用户重复提问场景有效 |

`.env` 相应调整：
```
RETRIEVAL_TOP_K=3          # 原为 8，过大会稀释证据密度
```

**需要新增的生产能力**（当前代码库不具备）：`RetrievalService` 目前只在 RRF 归一化分数上做门禁。落地余弦门禁需要在 `_retrieve_hybrid` 的融合前增加按 `vector_score` 的绝对阈值过滤，并把该阈值纳入 `CalibrationArtifact`（新增 `cosine_threshold` 字段）以便随模型/语料版本失效重标。

## 5. 遗留问题与后续动作

| # | 问题 | 影响 | 建议动作 |
|---|---|---|---|
| 1 | **删除残留 / 复核泄漏未真实覆盖** | 这两项零容忍指标当前是"假绿" | 构造负样本集（`deleted=true`、`retrieval_eligible=false` 记录），验证过滤链路 |
| 2 | **`candidate_limit` / `rerank_limit` 无法标定** | 生产回退到内部魔数（`max(top_k*5,50)`） | 语料扩充到 500+ 条后重跑参数矩阵 |
| 3 | **评估集仅 18 条用例** | 统计置信度有限，0.50 阈值可能过拟合 | 按方案 §3 阶段 1 建立 50~100 条真实种子集 |
| 4 | **私有库 4 条重复记录** | 占用 top_k 槽位（实测冗余度最高 0.667） | 清理调试残留；对入库做 `content_hash` 幂等去重 |
| 5 | **私有库 2 条乱码记录**（无中文字形，■ 占位） | 向量接近真实内容，可能挤占槽位；拉低查准 | 源文件本身缺 CJK 字形，**重跑解析无效，需换源文件** |
| 6 | **公共库为未审核示例语料** | 不可作为患者宣教依据 | 上线前替换为已审核语料并重建索引 |
| 7 | **重排阶段空转** | `rerank_model` 未配置，P95=0.0ms | 装配交叉编码器后重测，预期提升排序质量 |
