## 结论：**启用被阻塞。当前形态下无法启用，且暴露了一个既有 P0 缺陷。**

配置 artifact 后，**生产默认作用域（混合检索）的每一个查询都 fail-closed**：

```
artifact.index_version  作用域               返回   判定     reason
--------------------------------------------------------------------
public-v1               纯公共(H-EDUCATION)   3    PASS    None
public-v1               纯私有(REPORT)        0    FAIL    calibration_artifact_mismatch
public-v1               混合(LAB/ORDINARY)    0    FAIL    calibration_artifact_mismatch
private-v1              纯公共(H-EDUCATION)   0    FAIL    calibration_artifact_mismatch
private-v1              纯私有(REPORT)        3    PASS    None
private-v1              混合(LAB/ORDINARY)    0    FAIL    calibration_artifact_mismatch

生产默认作用域（混合）可用: False
```

**没有任何 `index_version` 取值能让混合作用域通过。**

---

## 根因：一致性检查拿「单一版本」比对「两个索引的记录」

`retrieval/service.py` 的 artifact 一致性检查：

```python
mismatched = [
    record
    for record in (*lexical, *vector)      # ← 公共 + 私有的全部候选
    if record.index_version != artifact.index_version   # ← 单一期望值
    or record.embedding_model != artifact.embedding_model
]
```

而两个索引的 `index_version` **按设计就不同**：

| 索引 | `index_version` | 来源 |
|---|---|---|
| `medical-rag-public-local` | **`public-v1`** | `KnowledgeIngestService(embedding_index_version="public-v1")`；镜像于 `ReconciliationService.DEFAULT_PUBLIC_INDEX_VERSION` |
| `medical-rag-private-local` | **`private-v1`** | `IndexJob.index_version` 默认；`Settings.embedding_index_version = "private-v1"` |

实测（`artifact_probe.json`）：公共 5 条全为 `public-v1`，私有 7 条全为 `private-v1`，
`embedding_model` 两侧一致（`BAAI/bge-small-zh-v1.5`）——**只有 `index_version` 冲突**。

项目本身是**显式按作用域建模版本**的，`ReconciliationService` 就分成两套：

```python
_PRIVATE_VERSION_KEYS = ("parser_version", "embedding_model", "index_version")
_PUBLIC_VERSION_KEYS  = ("parser_version", "index_version")
```

所以"公共与私有用不同版本"不是数据脏，而是**预期语义**；
检索侧用单一版本全局比对才是缺陷。

---

## 关键判定：这是**既有缺陷**，与余弦门禁无关

对照实验（`artifact_preexisting.json`，混合作用域）：

| 变体 | gate_policy | 返回 | reason |
|---|---|---|---|
| A. legacy artifact（仅 `threshold`） | `calibrated` | 0 | `calibration_artifact_mismatch` |
| B. cosine artifact（带 `cosine_threshold`） | `cosine_absolute` | 0 | `calibration_artifact_mismatch` |

一致性检查在门禁逻辑**之前**执行，A 与 B **同样失败**。

> **即：只要在双索引部署里配置任何 artifact，检索就已经整体不可用。**
> 之所以一直没暴露，是因为生产 `.env` 从未配置 `CALIBRATION_ARTIFACT_PATH`——
> 一致性检查整段被跳过。这是一个**潜伏至今的 P0**。

## 影响面（按生产真实路由）

`query/pipeline.py:_strategy_for` 决定的默认作用域：

| 意图 | 作用域 | 配 artifact 后 |
|---|---|---|
| `HEALTH_EDUCATION` | 纯公共 | ✅ 可用 |
| `REPORT_EXPLANATION` | 纯私有（有私有时） | ✅ 可用 |
| `LAB_INDICATOR` / `ORDINARY` | **混合** | ❌ **全部拒答** |
| 私有优先不足时的公共补检（`_backfill_public_evidence`） | 纯公共 | ✅ 可用 |

**`LAB_INDICATOR` 与 `ORDINARY` 是覆盖面最大的两类**——"我的血红蛋白是多少"这类
核心场景全部失效。这是"引入门禁反而让系统不可用"的最坏形态，比不启用更危险。

---

## 为什么单测没拦住

- `tests/unit/test_retrieval_service.py` 用 `_DisjointCandidates` 假索引，候选的
  `index_version` 取默认 `"private-v1"`，**两路同源**，永远自洽。
- `tests/integration/test_composition_wiring.py` 只断言 `gate_policy` / `cosine_threshold`
  等**构造期属性**，不跑真实检索，因此不触发运行期一致性检查。
- 真实链路验收脚本 `scripts/retrieval_cosine_gate_eval.py` 用的是**直接传
  `cosine_threshold` 参数**的路径（不传 artifact），恰好绕过一致性检查。

→ 存在一个**覆盖空洞**：`artifact + 双索引 + 混合作用域 + 真实记录` 四者同时出现的场景。

## 修复方向（建议，待批准后再动代码）

记录已经携带 `index_name`（`opensearch_store.py:431`），因此服务端**有能力**判定
每条候选属于哪个索引。推荐做法：

**按作用域分别比对版本**，而非全局单一版本。

两种落法：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | artifact 新增可选字段 `public_index_version` / `private_index_version`；比对时按 `record.index_name` 选择期望值 | 复用既有 `score_space` 的"可选新字段"模式；旧 artifact 行为不变 |
| B | 强制两索引共用同一 `index_version` | 需重建公共/私有索引，且与 `ReconciliationService` 的按作用域建模相冲突 |

**这不是放宽安全校验**——真正的安全性质是"每条记录与它所在索引的版本相符"，
而不是"所有记录与同一个常量相符"。方案 A 让该性质的表达**更精确**，而非更松。

向后兼容：两个新字段均可选；未提供时保持"全局单一版本"的既有语义
（即旧 artifact 行为逐字节不变，仍然 fail-closed），只有显式声明作用域版本
才启用新比对。

**开放问题（需你定）**：旧 artifact 缺这两个字段时，
- (a) 保持现状（全局比对，双索引下仍不可用）——最保守；
- (b) 全局比对只作用于**单一作用域**查询，混合作用域 fail-closed 并给出
  专门 reason——但混合是默认，等于仍不可用；
- (c) 缺字段时按"只校验 `embedding_model` + 每索引内部自洽"降级——
  会改变既有 fail-closed 语义，需独立验收。

我倾向 (a)：不改变旧 artifact 语义，新部署显式声明作用域版本。
