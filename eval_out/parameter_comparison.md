## 分母可及性体检（P@K 上界）

> 口径：排序指标按**内容去重**计算，故此处 gold 数也取去重后的**唯一内容数**（`medical-rag-private-local` 中同一 `blood_report.pdf` 的多条 chunk 共享一个 hash）。
> 上界 = `min(1, |gold| / K)`，K = 3。三态判定：`capped`（口径封顶，不可判定） / `pass` / `fail`。

> **结论：P@K 在本评估集上大部分被口径封顶**（12/14 条 `|gold| < K`）。因此 P@K=0.429 被判「未达标」是**标注口径问题，不是检索缺陷**——这些用例检索一条都没丢。要真正评估查准率，需把评估集每条标注的 gold 数提升到 ≥ K。

> 其中 `fail` 的 2 条（pub-lifestyle-all、priv-red-cell）上界未被锁死而实测偏低，属**真实检索缺口**（多与 Recall 未满相关），应单独归因，不与上面的口径问题混谈。

## 结论

- **混合检索优于任一单路**：MRR 词法 0.774 / 向量 0.917 / 混合 0.964。混合相对词法提升 +0.191，相对向量提升 +0.048。
- **RRF k 在本语料上几乎不敏感**：MRR 取值 {10: 0.964, 30: 0.964, 60: 0.964, 100: 0.964}，极差 0.000。原因是最优候选在两路中排名都很靠前，1/(k+rank) 的相对关系不随 k 变化。k=10 略优，但差异在噪声量级。
- **top_k 影响召回上限与上下文冗余**：k=1 → 召回 0.929 / 查准 0.929；k=3 → 召回 0.929 / 查准 0.429；k=5 → 召回 0.964 / 查准 0.271。召回随 k 单调上升，但查准与信息密度下降。**查准率（P@K）同时受 `min(1, |gold|/K)` 上界约束**——本评估集多数用例 `|gold| < K`，其 P@K 数值在口径上被封顶，见「分母可及性体检」一节，不能单以阈值判其达标与否。
- **candidate_limit 在当前语料上无区分度**：MRR 恒为 0.964。原因是候选池（public 18 + private 7）本身就小于任何被测上限，截断从未生效。**该参数的推荐值必须等语料规模上来后重新标定**，当前测得的'最优值'没有意义。
- **硬门禁会直接砍掉召回**：rank_gate=2 使召回降至 0.929、rank_gate=1 降至 0.714（无门禁为 0.929）。门禁语义必须显式声明（`GatePolicy`），且未标定时不应启用——否则 top_k 退化会被误读为低召回。
- **bge 查询指令前缀收益有限**：纯向量 MRR 0.917 → 0.845，混合 0.964 → 0.929。该前缀面向「短查询检索长文章」（s2p），而本项目 query 已是完整问句、文档块也只有百余字，场景不匹配。
- **向量缓存对单次延迟无改善**（P50 50ms vs 53ms）：每个 query 只编码一次，缓存命中率恒为 0。它的价值在多用户重复提问的场景。
- **零容忍安全项全配置通过**：20 个配置累计违规 0 次。越权用例以真实的不同患者/租户身份触发，ACL 过滤在候选生成阶段即生效（`_is_authorized` + OpenSearch filter），不依赖后置过滤。
- **删除残留 / 复核泄漏未真实覆盖**：当前语料中没有 `deleted=true` 或 `retrieval_eligible=false` 的记录，因此这两项只能证明「过滤逻辑未误伤」，不能证明「残留会被拦住」。需要专门的负样本集才能验证。
- **评估结论的边界（语料缺陷）**：私有库 7 条中仅 3 组唯一内容，其中 2 条为无中文字形的乱码记录（■ 占位）。这使：(a) 召回率必须在去重口径下解读；(b) 乱码记录因向量接近而可能挤占 top_k 槽位；(c) 本评估集规模偏小，结论的统计置信度有限。
- **样本量不足以确认召回达标**：默认配置 Recall@K = 0.929，但 n=14（<30）时 95% t 区间 [0.824, 1.000] 下界 < 阈值 0.90，结论：**n<30 暂不判定**。要达到「区间下界 ≥ 0.90」需把评估集扩到 ~1000 量级（按比例检验样本量公式估算），当前结论只能算「未观测到失败」，不能算「已确认达标」。
- **P@K「未达标」主要是口径封顶，不是检索缺陷**：14 条 quality 用例中 12 条满足 `|gold| < K`（去重后 |gold| 多为 1，K=3），查准率上界仅 0.333。这 12 条用例的 P@K **恰好压在上界**、召回均为 1.000——它们一条都没丢。用二元阈值判「未达标」犯了把标注缺陷当检索缺陷的错误；要真正评估 P@K，需把每条 gold 标注数提到 ≥ K。
